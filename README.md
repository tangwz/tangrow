# Tangrow

给现有 Obsidian 笔记库补充一个右侧工作台与原生 Bases。保留自己的目录、链接和笔记分类，用轻量入口完成捕获、收藏、写作、专注与习惯记录。

界面默认使用简体中文；已有配置中没有语言字段时，也使用中文。可在插件设置的「界面语言」中切换 English，侧栏、设置、命令与提示即时切换，速记输入和写作草稿保持不变。语言切换不重命名笔记或目录。

## 使用方式

| 工作区 | 日常用途 | 数据位置 |
| --- | --- | --- |
| 工具 | 按组使用当前页动作、新建笔记、只读报表与任务入口 | 原笔记和现有目录 |
| 速记 | 快速记录想法，按月历选日、查看当日时间线，打开独立速记窗口 | 配置的 Inbox 与共享草稿 |
| 收藏 | 收藏当前笔记，返回最近实际打开过的文件 | 原笔记的 `tangrow_pin` 属性与本地打开历史 |
| 写作 | 保存临时写作，再转成草稿笔记 | 插件草稿缓存与配置的 Inbox |
| 专注 | 开始、暂停、继续、结束专注 | 补充目录中的结构化记录 |
| 习惯 | 添加习惯、每日记录、查看近期连续情况 | 补充目录中的结构化记录 |

工具区按快捷、新建、当前文件、工作区和数据库分组，减少窄侧栏中的滚动。复制内链、复制路径和文件定位适用于当前活动文件，包括 `.base`；修改正文、封面和收藏等动作仅面向 Markdown。明暗主题可单击切换，主题与强调色设置另有入口。

速记月历按本地记录日期显示每天的数量，可选某一天，也可返回「全部日期」。时间线按创建时间从新到旧排列，每次加载 12 条；卡片展示约 240 字符的纯文本摘要，完整内容与编辑使用「打开原始笔记」。日期优先读取有效的 `created` 属性，缺失或无效时回退到文件创建时间；不会为了归入日期而搬动或改写原笔记。文件时间可能受导入、同步或恢复影响。

命令「Tangrow: 打开速记小窗」在桌面端打开分离窗口，在移动端使用主区标签页。它与侧栏使用同一份持久化速记草稿，窗口切换无需复制输入；保存仍写入原定 Inbox。收藏区的「最近打开」依据实际打开事件记录，最多保留 50 个本地路径，首次没有历史字段时从 Obsidian 的 `getLastOpenFiles()` 初始化，能回溯的初始范围由宿主已有列表决定；Markdown、Bases、Canvas 等文件均可记录，重命名和删除会同步维护路径。它与按修改时间查询的「近期修改」Bases 分开。

「打开报表」展示笔记总数、项目目录中的笔记数、正文任务、已保存专注时长和习惯记录等只读指标。项目指标统计的是笔记数，不是独立项目数。近 30 天图表按文件系统创建时间计数，导入、同步或恢复可能影响该时间；它不代表键盘活动或实际编辑时长。

Bases 是查询视图，不是另一份笔记存储。笔记、近期修改、项目、领域、资源、Inbox、来源、捕获、收藏、草稿、专注、习惯和任务笔记分别有独立入口。现有没有属性的笔记也能通过路径、文件名和修改时间进入基础视图。正文复选框由侧栏单独索引，未完成计数包含 `[ ]` 与 `[/]`；任务索引排除补充目录与归档目录。Bases 的任务视图只展示任务笔记，不能把每个正文复选框变成数据库行。「打开任务总览」遵循设置的 `taskOverviewPath`，默认打开现有 `10-Life(Meta)/12-Tasks.md`，保留其中的 Tasks 查询，不创建平行任务库。

## 安装

要求 Obsidian 1.10.0 或更新版本，并开启核心插件 Bases。桌面构建需要 Node.js 22 或更新版本，以及 npm；打包脚本还需要系统 `zip`。

```sh
npm ci
npm run build
npm test
npm run install:vault -- --vault /absolute/path/to/vault --dry-run
npm run install:vault -- --vault /absolute/path/to/vault
```

随后在 Obsidian 的 Community plugins 中启用 Tangrow。也可以在安装命令后增加 `--enable`，将插件 ID 追加到现有启用列表；如果应用已经运行，重新加载应用后生效。安装器不修改受限模式，不自动批准其他插件。若安装期间启用列表被 Obsidian 修改，安装器会保留最新列表并停止启用步骤；此时运行文件已经安装，可在应用内启用 Tangrow 或重新运行安装命令。

安装器只写入 `.obsidian/plugins/tangrow/manifest.json`、`main.js` 和 `styles.css`，不会覆盖 `data.json`。替换已有文件或启用列表前，会将原文件备份到用户主目录的 `.local/state/tangrow/backups`。它不触碰现有 Markdown、目录分类或 `workspace.json`，并拒绝通过插件路径的符号链接写入。

首次使用时打开命令面板，执行「Tangrow: 打开侧栏」；在设置中核对路径，再执行「Tangrow: 初始化补充数据库」。英文界面的对应命令为 `Tangrow: Open companion` 和 `Tangrow: Set up companion Bases`。首次初始化只新增补充目录和缺失的视图文件；只有全部 13 个数据库及补充说明文件都存在时，初始化状态才显示为就绪。默认位置为 `10-Life(Meta)/Tangrow`，普通新笔记仍进入 `00-Inbox`；新项目默认在 `20-Project` 下创建以标题命名的子目录，并将项目笔记放入其中，也可明确选择已有项目子目录，不在项目根目录平铺笔记。可在插件设置中替换为自己已有的路径，无需重新组织目录。修改目录设置不会改写已有 Bases；如需调整旧视图，请手动修改其筛选条件，或选择新的补充目录后重新初始化。

数据库的视图名称、列显示名及补充说明跟随界面语言；`.base` 文件名和属性键保持英文且稳定，已有链接不受影响。升级或切换语言时，只更新仍匹配已知生成版本的数据库和 Tangrow 说明文件；数据库比较忽略 Obsidian 自动调整的 YAML 排版与对象键顺序，但筛选条件、显示名、额外设置及注释的自定义修改都会保留原文件。补充说明文档按完整文本匹配。

## 数据约定

插件使用 `tangrow_` 前缀属性，避免与已有 `type`、`status`、`created`、`source` 等字段冲突。初始化不批量补齐属性，也不迁移旧笔记；收藏、封面、标题日期和正文时间戳只在明确触发对应动作时修改当前页。标题日期会给正文第一个一级标题补充 `YYYY-MM-DD`；没有一级标题时创建一个。该动作不重命名文件或路径，也不替换选中文字；正文时间戳是独立动作。

- 捕获、草稿和普通笔记遵循配置的 Inbox；项目笔记进入新建或明确选择的项目子目录。
- 专注和习惯是独立 Markdown 记录，可以在 Bases 中查看，也可以直接编辑。
- `data.json` 的 `composer` 保存侧栏与独立窗口共享的未提交速记及写作标题，写作正文继续保存在 `scratch` 字段；切换工作区、语言或重启后恢复输入。
- 若速记已经写入 Inbox，但草稿清理状态保存失败，会提示速记已保存并重试状态保存。若应用在重试前退出，旧草稿可能在重启后恢复；再次保存前应核对已存在的速记。窗口间同时提交同一份草稿会合并为一次创建，不承诺进程崩溃后的跨重启去重。
- 最近打开历史仅保存在本地插件数据中，最多 50 个路径；它记录打开顺序，不以文件修改时间推测访问行为。
- 进行中的专注状态也保存在 `data.json`。暂停不会累计工作时长；完成记录按会话身份幂等写入，恢复或重试沿用已保存的分钟数，避免重复记录与时长漂移。
- 习惯定义持久化失败时回滚内存状态；已有打卡记录独立保留。
- 日记入口遵循配置的 Journal 路径与日期格式；已有日记会直接打开。
- 不发送笔记、统计或使用数据到外部服务，不需要账户或订阅。

原生主题、文件树定位与堆叠标签页没有完整公开的宿主接口；兼容适配器仅在运行时确认可用后调用，失败时提供原生操作指引，不直接写宿主私有配置。行宽由插件作用域样式控制，卸载后恢复。升级 Obsidian 后应复核这些宿主集成功能。

## 对照检查与尚未覆盖

本项目实现已确认的通用工作流，不宣称与参考界面所有功能完全等价。

| 对照项 | 当前范围 | 差异性质 |
| --- | --- | --- |
| 可见核心工具 | 具备 17 项工具对应入口，但刷新、宽度、折叠、封面、面板和颜色操作存在范围差异 | 通用入口覆盖，不等于逐项完全等价 |
| 速记日历、按日时间线与独立窗口 | 已提供日期筛选与当日速记；桌面使用分离窗口，移动端使用主区标签页，共享同一草稿 | 已覆盖的通用工作流与平台差异 |
| 最近访问 | 收藏区显示真实最近打开历史，保留至多 50 个本地路径；「近期修改」Bases 继续独立存在 | 已覆盖，访问与修改分开 |
| 报表高级指标 | 未覆盖全库字数、日记与速记连续值、孤岛、完成率、90 天分类增量、多曲线、随机漫步及八分页 | 功能缺口 |
| 全局键盘与编辑活跃时段 | 尚未实现；报表仅统计文件时间、任务与已保存专注记录，没有活跃分钟及时间范围筛选 | 功能缺口 |
| 列表折叠与展开 | 调用编辑器 `foldAll` / `unfoldAll`，会折叠可折叠章节，不限于列表 | 行为差异 |
| 已知质量边界 | Studio 多视图覆盖保护、超长摘要处理上限、习惯逐日读屏信息及辅助目录祖先冲突校验尚未完善 | 明确列入审计，未冒称已修 |
| 未展开的高级写作、专注与习惯行为 | 参考行为未完整核验；当前提供独立的基础工作流 | 未核验范围 |
| 布局、账户和联网机制 | 独立布局、本地数据、无需账户 | 有意采用的独立设计，不属于功能等价证明 |

完整的 17 项工具映射、13 项报表对照、数据库口径和已知界面问题见 [PARITY-AUDIT.md](docs/PARITY-AUDIT.md)。审计区分已修缺陷、尚未覆盖、语义差异、无法从截图判断的行为与有意采用的独立设计；不能用来源独立来替代功能完整性。

## 开发与验证

```sh
npm run dev
npm run typecheck
npm test
npm run build
npm run package
```

`npm run package` 生成 `dist/tangrow-0.2.1.zip`，包含运行文件、MIT 许可和第三方声明。`main.js`、依赖与发布包不提交到源码仓库。

安装后的人工验收：

1. 对照原库，确认顶层目录和原笔记路径保持不变，新增内容仅位于补充目录及插件目录。
2. 打开笔记与 Bases，切换六个工作区和工具分组；空列表、无活动页、窄侧栏与深色模式都应可用，Bases 当前页也可复制链接和定位。
3. 保存速记、收藏当前页、转存草稿、新建或选择项目子目录，确认路径和数据库结果；标题日期只修改正文一级标题。
4. 开始专注，暂停后等待，确认剩余时间不变；继续、重启、结束及失败重试后检查记录没有重复，已保存分钟数不漂移。
5. 同日多次点击习惯记录，确认一天只有一条；隔日检查近期网格与连续天数。
6. 在速记和写作区输入未保存文字，再切换界面语言，确认文案即时变化、输入保持，数据库路径和已有链接不变。
7. 打开只读报表，核对项目笔记数和 `[ ]` / `[/]` 任务；任务总览应打开原有任务页，初始化提示应反映全部数据库是否存在。
8. 在月历中跨月选日，核对速记时间线；有效 `created` 和缺失时的文件时间回退应各自归入正确日期。
9. 在侧栏与独立速记窗口切换输入和保存，确认同一草稿同步；移动端应使用主区标签页。
10. 依次打开不同文件而不修改，确认「最近打开」顺序随打开变化，且不影响「近期修改」Bases。
11. 关闭并重新启用插件，确认原笔记、其他插件与工作区不受影响。
