# Tangrow

给现有 Obsidian 笔记库补充一个右侧工作台与原生 Bases。保留自己的目录、链接和笔记分类，用轻量入口完成捕获、收藏、写作、专注与习惯记录。

界面默认使用简体中文；已有配置中没有语言字段时，也使用中文。可在插件设置的「界面语言」中切换 English，侧栏、设置、命令与提示即时切换，速记输入和写作草稿保持不变。语言切换不重命名笔记或目录。

## 使用方式

| 工作区 | 日常用途 | 数据位置 |
| --- | --- | --- |
| 工具 | 按组使用当前页动作、新建笔记、可直接修改状态的报表与任务入口 | 原笔记和现有目录 |
| 速记 | 快速记录想法，按月历选日、查看当日时间线，打开独立速记窗口 | 配置的 Inbox 与共享草稿 |
| 收藏 | 收藏当前笔记，返回最近实际打开过的文件 | 原笔记的 `tangrow_pin` 属性与本地打开历史 |
| 写作 | 保存临时写作，再转成草稿笔记 | 插件草稿缓存与配置的 Inbox |
| 专注 | 开始、暂停、继续、结束专注 | 补充目录中的结构化记录 |
| 习惯 | 添加习惯、每日记录、查看近期连续情况 | 补充目录中的结构化记录 |
| AI | 总结、提取任务、润色、续写、提问与回顾；默认关闭 | 结果由你选择写入位置，不自动改动笔记 |

### 快速新建

侧栏顶部固定一排入口：速记、笔记、任务、项目，旁边的「＋」和命令「Tangrow: 快速新建」打开同一个弹窗。弹窗只有一个输入框，`⌘ / Ctrl + 1–4` 切换类型，`⌘ / Ctrl + Enter` 保存：

- 速记：原样存入 Inbox。
- 笔记：第一行是标题，其余是正文，存入 Inbox。
- 任务：每行一条，可选截止日期（以 `📅 YYYY-MM-DD` 追加在行尾），写入任务总览末尾或今日日记。任务总览必须已存在，不另建任务库。
- 项目：第一行是项目名，新建项目子目录或放进已有项目目录。

勾选「保存后继续」可以连续录入。「Tangrow: 新建笔记／新建任务／新建项目」三个命令直接打开对应类型，可以各自绑定快捷键。在编辑器里选中文字后，右键菜单可以把选中内容加为任务或存为速记。

主页显示今天的日期、待办、待整理速记、项目和笔记数量，点击数字进入对应位置。任务列表顶部可以直接输入并回车添加；点任务前的圆圈会在原笔记里把这一行勾选为完成，点文字跳到原文。如果那一行在索引之后被改过，勾选会停止并提示打开笔记查看。

### AI 助手

AI 功能默认关闭。在设置的「AI 助手」中开启并填写自己的 Anthropic API 密钥后可用；密钥优先保存在 Obsidian 的密钥存储中（1.11.4 及以上），旧版本保存在本插件的 `data.json`。模型默认 `claude-opus-5-5`，可改成其他 Claude 模型 ID。

- AI 工作区：选择处理对象（当前笔记、选中文本、写作草稿、今天、本周），再点总结要点、提取任务、标题与标签、润色、续写，或直接提问。选「今天」「本周」时生成回顾，素材是这段时间保存的速记、新建和修改过的笔记名、未完成任务以及专注和打卡数量。
- 结果先显示在侧栏，可以复制、插入光标处、追加到笔记末尾、存为新笔记、替换或加入写作草稿；提取出的任务可以一键送进快速新建，确认后再保存。
- 快速新建里的「AI 分拣」和速记处理弹窗里的「AI 建议」会给出类型、标题、截止日期和关联项目的建议，只填表单，不保存。
- 「打开协作约定」在补充目录生成 `AGENTS.md`，用当前设置说明各目录的用途和 `tangrow_` 属性，供 Claude Code 等外部助手阅读。它不需要密钥，已有文件只打开、不覆盖。

发送范围：只有点击上述操作时，才把所选内容用你的密钥直接发到 Claude API；内容过长会提示缩小范围，不会截断后发送。请求可能产生 API 费用。不开启 AI 时，插件不发起任何网络请求。

工具区按今天、新建、当前文件、工作区和数据库分组，减少窄侧栏中的滚动。复制内链、复制路径和文件定位适用于当前活动文件，包括 `.base`；修改正文、封面和收藏等动作仅面向 Markdown。明暗主题可单击切换，主题与强调色设置另有入口。

速记月历按本地记录日期显示每天的数量，可选某一天，也可返回「全部日期」。时间线按创建时间从新到旧排列，每次加载 12 条；卡片展示约 240 字符的纯文本摘要，只对原文前 16,384 个 UTF-16 码元做格式清理，省略后文时显示省略号。属性区超出该范围或不完整时不展示摘要，完整内容与编辑使用「打开原始笔记」。日期优先读取有效的 `created` 属性，缺失或无效时回退到文件创建时间；不会为了归入日期而搬动或改写原笔记。文件时间可能受导入、同步或恢复影响。

速记时间线默认显示「待处理」，也可切换到「已处理」或「全部速记」，并与选中的日期组合筛选。月历继续显示各天保存过的全部速记数量。点击卡片的「处理速记」选择下一步：

- 转为正式笔记：输入标题，复制正文到配置的 Inbox；选择已有项目笔记时，放到该项目笔记所在目录并建立关联。原速记保留，双方记录来源与结果链接。
- 追加到任务总览：输入任务标题，在已配置的任务总览末尾追加一条正文复选框和来源链接，保留原查询和其他内容。任务总览必须已经存在。
- 关联项目：选择现有项目笔记，为原速记建立关联并标记已处理，文件位置保持。
- 标记已处理：保留原文，将这条速记移入已处理列表。

处理成功后可点击「打开处理结果」，由用户决定何时离开当前工作位置。中途失败的卡片提供「继续处理」，重试会识别已经生成或移动过的结果，避免重复创建。已处理卡片可「恢复为待处理」；已保存的笔记、任务和来源链接保留。

命令「Tangrow: 打开速记小窗」在桌面端打开分离窗口，在移动端使用主区标签页。它与侧栏使用同一份持久化速记草稿，窗口切换无需复制输入；保存仍写入原定 Inbox。收藏区的「最近打开」依据实际打开事件记录，最多保留 50 个本地路径，首次没有历史字段时从 Obsidian 的 `getLastOpenFiles()` 初始化，能回溯的初始范围由宿主已有列表决定；Markdown、Bases、Canvas 等文件均可记录，重命名和删除会同步维护路径。它与按修改时间查询的「近期修改」Bases 分开。

速记日历位于输入区上方，以紧凑的整月布局提供年、季、月、周、日五个周期入口。先选择日期，再点击对应按钮，打开或创建该周期的 Markdown 笔记；切换月份会选中该月 1 日。「今天」恢复当前日期，「全部日期」恢复全部速记时间线。新笔记位于配置的日记目录中；已有日记的日期格式保持不变，其他周期默认按 `Weekly`、`Monthly`、`Quarterly`、`Yearly` 子目录组织，可在设置的「周期笔记」中分别调整 Moment 路径格式与模板。周记采用周一开始的 ISO 周，默认使用 `GGGG` 周所属年和 `WW` 周数，跨年同一周只对应一个路径。

模板只用于第一次创建，支持 `{{title}}`、`{{date}}`、`{{start}}`、`{{end}}`、`{{period}}`、`{{year}}`、`{{week}}` 和 `{{quarter}}`；日期对应周期起点，结束日期包含当天。模板正文与属性由模板本身决定，不执行 Templater 等模板脚本。没有模板时生成周期属性与标题。已有文件直接打开，不补写属性或重新应用模板，也不自动迁移其他日记插件的配置。

点击输入区底部的展开图标，或执行「Tangrow: 全屏沉浸速记」，可铺满窗口记录；侧栏、小窗和沉浸速记仍共享同一草稿。`⌘ / Ctrl + Enter` 保存速记，`Esc` 或退出按钮返回，未提交内容继续保留。任意 Markdown 笔记可点击标题栏的展开图标，或通过「Tangrow: 切换当前笔记沉浸模式」进入或退出，继续使用原生编辑器与自动保存。支持 Fullscreen API 的宿主还提供「切换系统全屏」按钮；系统全屏与窗口内沉浸是两个层级。切换笔记或停用插件时清理沉浸布局。

「打开报表」提供总览、行动、任务、项目、笔记、剪藏、领域、时间八页。项目与领域按直接子目录及根级独立笔记识别实体，任务按正文复选框识别；支持完成率、近 90 天新增、字词统计、连续记录、孤岛和至多 10 篇的随机回顾队列。新增趋势是现有记录按创建日的分布，不是历史状态曲线。具体分母、日期与排除范围见 [REPORTING.md](docs/REPORTING.md)。

「时间」页展示本地编辑事件估算的活跃分钟、小时分布和每日目标，支持今天及近 7／30／60／90／180／365 天。采集可关闭，只从本版本保存事件汇总，没有历史回填；它不保存正文、按键或活跃文件路径，也不等于精确键盘持续时长。已保存专注分钟另行统计。

Bases 是查询视图，不是另一份笔记存储。笔记、近期修改、项目、领域、资源、Inbox、来源、捕获、收藏、草稿、专注、习惯和任务笔记分别有独立入口。现有没有属性的笔记也能通过路径、文件名和修改时间进入基础视图。正文复选框由侧栏单独索引，未完成计数包含 `[ ]` 与 `[/]`；任务索引排除补充目录与归档目录。Bases 的任务视图只展示任务笔记，不能把每个正文复选框变成数据库行。「打开任务总览」遵循设置的 `taskOverviewPath`，默认打开现有 `10-Life(Meta)/12-Tasks.md`，保留其中的 Tasks 查询，不创建平行任务库。

## 安装

要求 Obsidian 1.10.0 或更新版本，并开启核心插件 Bases。桌面构建需要 Node.js 22 或更新版本，以及 npm；打包和归档回归需要系统 `zip`、`unzip`。

```sh
npm ci
npm run build
npm test
npm run install:vault -- --vault /absolute/path/to/vault --dry-run
npm run install:vault -- --vault /absolute/path/to/vault
```

随后在 Obsidian 的 Community plugins 中启用 Tangrow。也可以在安装命令后增加 `--enable`，将插件 ID 追加到现有启用列表；如果应用已经运行，重新加载应用后生效。安装器不修改受限模式，不自动批准其他插件。若安装期间启用列表被 Obsidian 修改，安装器会保留最新列表并停止启用步骤；此时运行文件已经安装，可在应用内启用 Tangrow 或重新运行安装命令。

安装器在 `.obsidian/plugins/tangrow/` 部署 `manifest.json`、`main.js`、`styles.css`、`LICENSE`、`NOTICE`、`LICENSE-MIT-LEGACY` 和 `THIRD_PARTY_NOTICES.md` 七个文件，不会覆盖 `data.json`。替换已有文件或启用列表前，会将原文件备份到用户主目录的 `.local/state/tangrow/backups`。它不触碰现有 Markdown、目录分类或 `workspace.json`，并拒绝通过插件路径的符号链接写入。交付 ZIP 或已安装的插件目录时，应保留 GPL、项目附加声明、旧 MIT 全文和第三方声明，并按 GPL 提供对应源码。

首次使用时打开命令面板，执行「Tangrow: 打开侧栏」；在设置中核对路径，再执行「Tangrow: 初始化补充数据库」。英文界面的对应命令为 `Tangrow: Open companion` 和 `Tangrow: Set up companion Bases`。首次初始化只新增补充目录和缺失的视图文件；只有全部 13 个数据库及补充说明文件都存在时，初始化状态才显示为就绪。补充目录默认位于笔记库根目录的 `99-Tangrow`，普通新笔记仍进入 `00-Inbox`；新项目默认在 `20-Project` 下创建以标题命名的子目录，并将项目笔记放入其中，也可明确选择已有项目子目录，不在项目根目录平铺笔记。可在插件设置中替换为自己已有的路径，无需重新组织目录。修改目录设置不会改写已有 Bases；如需调整旧视图，请手动修改其筛选条件，或选择新的补充目录后重新初始化。

升级不会自动改动已保存的补充目录。需要把旧目录提升到库根时，使用设置中的迁移按钮，或命令「Tangrow: 将辅助目录迁移到 99-Tangrow」（英文为 `Tangrow: Move companion folder to 99-Tangrow`）：目标固定为 `99-Tangrow`，目标已存在时停止，不合并或覆盖。迁移会移动整个辅助目录，包括用户放入其中的自定义笔记及其他文件。迁移通过宿主处理文件链接，保留宿主更新后的链接路径；未定制的 Bases 与说明文件跟随新存储路径更新，自定义正文和查询不以生成模板覆盖，并提示手动检查。失败时尝试恢复原目录和配置，原位置新出现的用户文件会保留；若恢复不完整，会提示核对实际路径后再重试。

补充目录不能与配置的内容目录相同，也不能包含内容目录；内容目录内可以使用专属补充子目录。修改任一目录时都会检查完整配置。已有冲突配置会保留供修正，但不会据此从统计中排除用户笔记，并且会阻止在该辅助目录下生成文件。

数据库的视图名称、列显示名及补充说明跟随界面语言；`.base` 文件名和属性键保持英文且稳定，已有链接不受影响。升级或切换语言时，只更新仍匹配已知生成版本的数据库和 Tangrow 说明文件；数据库比较忽略 Obsidian 自动调整的 YAML 排版与对象键顺序，但筛选条件、显示名、额外设置及注释的自定义修改都会保留原文件。补充说明文档按完整文本匹配。

## 数据约定

插件使用 `tangrow_` 前缀属性，避免与已有 `type`、`status`、`created`、`source` 等字段冲突。初始化不批量补齐属性，也不迁移旧笔记；收藏、封面、标题日期和正文时间戳只在明确触发对应动作时修改当前页。标题日期会给正文第一个一级标题补充 `YYYY-MM-DD`；没有一级标题时创建一个。该动作不重命名文件或路径，也不替换选中文字；正文时间戳是独立动作。

- 捕获、草稿和普通笔记遵循配置的 Inbox；项目笔记进入新建或明确选择的项目子目录。
- 专注和习惯是独立 Markdown 记录，可以在 Bases 中查看，也可以直接编辑。
- `data.json` 的 `composer` 保存侧栏与独立窗口共享的未提交速记及写作标题，写作正文继续保存在 `scratch` 字段；各写作视图实时同步正文和标题，切换工作区、语言或重启后恢复输入。中文输入法组字期间，其他写作视图暂时只读，组字结束或关闭当前视图后恢复。
- 同时归档同一版本的写作草稿只创建一篇笔记，保存过程中输入的新内容会保留。笔记写入失败时保留草稿；写入已成功但自动打开失败时只提示打开问题，原稿不会再次作为未保存内容提交。
- 共享速记和写作草稿在创建笔记前，先持久化提交身份与目标路径，并在新笔记中写入 `tangrow_submission_id`。笔记已落盘、清理状态保存失败时，重启会直接读取文件核对并清理已提交的旧稿；文件被移动时也会查找同一身份。尚未落盘的草稿保留，重试沿用原提交身份和路径。保存期间的新编辑有独立身份，正文相同也不会被误清理或去重。
- 提交凭据保存在 `data.json` 的 `submissions` 字段，数据版本升级为 5，已有草稿原文与设置保持。无法保存凭据时不创建笔记；遇到不可读文件或无关同名文件时保留草稿，不覆盖原文件。此恢复只覆盖新版建立凭据的提交，不追溯识别旧版产生的重复记录，也不提供同步工具回滚数据或多个独立进程并行写入时的事务保证。
- 速记处理状态使用 `tangrow_processed_at`，结果链接使用 `tangrow_capture_result`；未完成的多文件动作在原速记的 `tangrow_capture_processing` 属性中保存凭据。转出的笔记带 `tangrow_source` 和处理身份，任务带来源链接和身份标记。恢复待处理只改变处理状态，不删除既有结果。
- 最近打开历史仅保存在本地插件数据中，最多 50 个路径；它记录打开顺序，不以文件修改时间推测访问行为。
- 进行中的专注状态也保存在 `data.json`。暂停不会累计工作时长；完成记录按会话身份幂等写入，恢复或重试沿用已保存的分钟数，避免重复记录与时长漂移。
- 习惯定义持久化失败时回滚内存状态；已有打卡记录独立保留。
- 日记入口遵循配置的 Journal 路径与日期格式；已有日记会直接打开。
- 编辑活跃只在本地持久化开始时间和时长桶；其他既有数据如最近打开、专注关联仍可包含本地路径。除非你开启 AI 并点击某个 AI 操作，插件不向任何外部服务发送笔记、统计或使用数据；不需要 Tangrow 账户或订阅。AI 的发送范围见「AI 助手」。

原生主题、文件树定位与堆叠标签页没有完整公开的宿主接口；兼容适配器仅在运行时确认可用后调用，失败时提供原生操作指引，不直接写宿主私有配置。行宽由插件作用域样式控制，卸载后恢复。升级 Obsidian 后应复核这些宿主集成功能。

## 对照检查与尚未覆盖

本项目实现已确认的通用工作流，不宣称与参考界面所有功能完全等价。

| 对照项 | 当前范围 | 差异性质 |
| --- | --- | --- |
| 可见核心工具 | 具备 17 项工具对应入口，但刷新、宽度、折叠、封面、面板和颜色操作存在范围差异 | 通用入口覆盖，不等于逐项完全等价 |
| 速记日历、按日时间线与独立窗口 | 已提供日期筛选与当日速记；桌面使用分离窗口，移动端使用主区标签页，共享同一草稿 | 已覆盖的通用工作流与平台差异 |
| 最近访问 | 收藏区显示真实最近打开历史，保留至多 50 个本地路径；「近期修改」Bases 继续独立存在 | 已覆盖，访问与修改分开 |
| 报表高级指标 | 已提供八页、字词统计、连续值、孤岛、完成率、90 天新增、多序列与随机回顾；规则在统计文档中公开 | 覆盖通用能力，隐藏参考口径未知 |
| 编辑活跃与时段 | 按当前可见、聚焦编辑器的实际编辑事件保守估算，提供时间范围与可配置目标 | 不追踪完整键盘行为，无历史回填 |

| 已知质量边界 | 摘要已有处理上限与异常 Markdown 保护；习惯逐日读屏信息尚未完善；写作多视图保护和辅助目录冲突校验已有对应实现 | 剩余问题继续列入审计 |

## 年度热力图

报表「笔记」页用一张年度热力图同时表示新笔记与当前收藏：浅紫为新笔记、深紫为收藏、双色为两者都有、灰色为都没有。颜色区分类型，不按数量分五档；数量由悬停、读屏或点击日期查看。每列一周、每格一天，支持年份切换、方向键和窄窗口横向滚动，独立于近期天数范围。

新笔记按本地文件创建日统计，排除有效辅助目录与笔记统计排除目录；收藏遵循全库显式收藏范围，按 `tangrow_pinned_at` 统计。取消收藏会移出图，重新收藏使用新日期；旧收藏日期缺失或无效会提示，不推测补写历史。它表示当前文件分布，不是完整收藏日志或编辑活跃图。

## 开发与验证

```sh
npm run dev
npm run typecheck
npm test
npm run build
npm run package
```

`npm run package` 生成 `dist/tangrow-0.4.0.zip`，包含运行文件、GPL 全文、项目附加声明、旧 MIT 全文和第三方声明。发布时还须提供与运行文件实际对应的完整源码；获取方式见 [LICENSING.md](docs/LICENSING.md)。`main.js`、依赖与发布包不提交到源码仓库。

打包前会核对包版本、GPL 元数据、七文件清单和构建首部；旧版本、旧 MIT 或旧专有许可首部的运行文件会被拒绝，应先重新构建。

安装后的人工验收：

1. 对照原库，确认顶层目录和原笔记路径保持不变，新增内容仅位于补充目录及插件目录。
2. 打开笔记与 Bases，切换六个工作区和工具分组；空列表、无活动页、窄侧栏与深色模式都应可用，Bases 当前页也可复制链接和定位。
3. 保存速记、收藏当前页、转存草稿、新建或选择项目子目录，确认路径和数据库结果；标题日期只修改正文一级标题。
4. 开始专注，暂停后等待，确认剩余时间不变；继续、重启、结束及失败重试后检查记录没有重复，已保存分钟数不漂移。
5. 同日多次点击习惯记录，确认一天只有一条；隔日检查近期网格与连续天数。
6. 在速记和写作区输入未保存文字，再切换界面语言，确认文案即时变化、输入保持，数据库路径和已有链接不变。
7. 打开八页报表，核对项目／领域实体与所含笔记数分开、`[ ]` / `[/]` 任务及完成率分母；任务总览应打开原有任务页。初始化提示应反映全部数据库是否存在。
8. 在月历中跨月选日，核对速记时间线；有效 `created` 和缺失时的文件时间回退应各自归入正确日期。
9. 在侧栏与独立速记窗口切换输入和保存，确认同一草稿同步；移动端应使用主区标签页。
10. 依次打开不同文件而不修改，确认「最近打开」顺序随打开变化，且不影响「近期修改」Bases。
11. 在两个写作视图交错编辑、中文组字及同时归档，确认新稿不会被旧视图或旧保存结果覆盖，归档只创建一篇。
12. 仅在副本中核对显式迁移：整个辅助目录及其中自定义文件移动至 `99-Tangrow`，链接与生成查询跟随更新、自定义内容不以模板覆盖；目标占用时停止。升级本身不调用迁移。
13. 对照统计文档核对剪藏、日记、孤岛索引待确认、编辑活跃采样及周期目标；改变笔记统计排除目录时，原文与 Bases 不变。
14. 核对单张年度图的四种类型与日期明细、原文入口，以及插件目录中的运行文件、GPL、项目附加声明、旧 MIT 全文与第三方声明；关闭并重新启用插件，确认原笔记、其他插件与工作区不受影响。
15. 在日历选日，依次打开日、周、月、季、年笔记，核对路径、周期起止、模板与已有正文；对照跨年 ISO 周和闰年二月。用自定义路径格式适配已有目录后，再开始创建。
16. 在侧栏、小窗和沉浸速记间切换输入，退出后草稿应保留；核对保存快捷键、退出按钮、中文输入法及系统全屏。对已有 Markdown 使用沉浸命令，切换文件和停用插件后应恢复布局。
17. 用快速新建各存一条速记、笔记、任务和项目，核对路径；任务总览中原有查询保持不变。在主页勾选一条任务，确认只有原笔记的那一行变为 `[x]`。
18. 未开启 AI 时确认没有网络请求；开启后对一篇测试笔记运行总结和提取任务，确认结果只在你选择后写入，停止按钮可中断。
