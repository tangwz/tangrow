# 设计与边界

Tangrow 是现有笔记系统的补充层。目录仍表达用户原有的组织方式，Bases 提供跨目录检索，右侧工作台提供动作入口。三者各自承担清楚的职责，避免为了使用插件而迁移整个笔记库。

## 信息与动作

| 用户意图 | 侧栏入口 | 持久化方式 |
| --- | --- | --- |
| 找到最近写过的内容 | Tools / 近期修改 | 读取宿主文件索引 |
| 新建、记录想法 | Tools / Capture | 原有 Inbox 或项目目录 |
| 返回重要笔记 | Pins | 当前页的命名空间属性 |
| 暂存写作再归档 | Studio | 临时文本先存插件数据，转存后成为草稿笔记 |
| 记录一段专注 | Focus | 会话状态与独立 Markdown 记录 |
| 坚持重复行动 | Habits | 习惯定义与按日记录 |
| 按维度浏览 | Bases 入口 | 原生 `.base` 查询配置 |

界面使用独立的分区、文字、间距与工具排列。样式跟随 Obsidian 的主题变量，采用原生图标 API，并将覆盖样式限制在 Tangrow 容器及明确的行宽标记中。窄侧栏保留滚动和键盘焦点，正文编辑不应被定时器刷新打断。

## 保留已有组织

默认路径对应已有目录角色，但都可以配置。初始化只创建 Tangrow 专属补充目录和缺失文件；不移动现有文件，不替换已有模板，不重写原有分类字段。对项目、领域和资源的筛选使用目录；对 Tangrow 新增记录使用 `tangrow_` 属性。

修改目录设置不会改写已经存在的 Bases，避免覆盖用户对视图的调整。需要改动旧查询时，手动更新筛选条件，或选择新的补充目录后重新初始化。

现有 `status: active` 可能表达项目状态，不应推断为任务未完成。正文任务由元数据索引单独读取；任务 Bases 明确以笔记为粒度，不宣称提供逐条复选框数据库。

## 稳定的边界

- 插件层负责宿主交互、订阅与写入；纯逻辑模块负责时间和视图定义，便于独立验证。
- 原文写入使用公开 Vault / FileManager API；属性修改集中在用户明确触发的动作中。
- 新建文件不覆盖同名文件；同一习惯和日期、同一专注会话应有稳定记录身份，避免重复写入。
- 进行中的状态与界面草稿持久化；暂停后的时间计算不依赖持续运行的定时器。
- 界面计时与笔记索引更新解耦，避免每秒重建编辑区域或扫描正文。
- 核心交互使用公开宿主接口；原生主题、文件树与标签页动作隔离在兼容适配器，运行时探测能力，失败时提供操作指引，不直接写宿主私有配置。

## 修改与撤回

停用插件即可撤去工作台和样式。原生 Bases 与已生成的 Markdown 仍可使用。移除插件前可先保留 `data.json`；它含临时写作、习惯定义及进行中的状态。是否删除补充视图、记录或笔记属性由用户自行决定，卸载不会自动删除内容。

安装脚本只部署三个运行文件，可独立备份和恢复；已有笔记和工作区不参与部署。备份目录中的 `restore.json` 记录原文件的目标位置，恢复时应先关闭 Obsidian，逐项核对后复制原文件。
