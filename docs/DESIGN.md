# 设计与边界

Tangrow 是现有笔记系统的补充层。目录仍表达用户原有的组织方式，Bases 提供跨目录检索，右侧工作台提供动作入口。三者各自承担清楚的职责，避免为了使用插件而迁移整个笔记库。

记录、知识与写作的下一阶段设计见 [统一设计方案](ZETTELKASTEN.md)，共同术语见 [领域语言](../CONTEXT.md)。该方案包含 Journal、速记、素材、卡片与稿件的关系及分期计划。其中已实现今天、创作、知识、AI 与「更多」五区导航，知识区的素材、卡片、主题与回顾列表，新建卡片与选中文本提炼为卡片，每日卡片回顾，以及卡片报表明细；三项新 Bases、通用提炼凭据、稿件候选与正文引用等其余部分尚未实现。本文描述当前实现与约束，未实现部分以统一设计方案为准。

## 信息与动作

| 用户意图 | 侧栏入口 | 持久化方式 |
| --- | --- | --- |

| 新建、记录想法 | 工具 / 速记 | 原有 Inbox，或新建、明确选择的项目子目录 |
| 返回重要笔记与最近访问 | 收藏 / 最近打开 | 当前页的命名空间属性与最多 50 个本地路径 |

| 按日、周、月、季、年记录 | 日历周期入口 / 命令 | 日记目录中的原生 Markdown，已有笔记直接打开 |
| 沉浸式记录 | 速记展开 / 当前笔记沉浸命令 | 速记沿用共享草稿；周期笔记沿用原生编辑器自动保存 |

| 记录一段专注 | 专注 | 会话状态与独立 Markdown 记录 |
| 坚持重复行动 | 习惯 | 习惯定义与按日记录 |
| 按维度浏览 | Bases 入口 | 原生 `.base` 查询配置 |
| 查看概况与任务 | 报表 / 既有任务总览 | 只读聚合与现有 Tasks 笔记 |
| 随手新建速记、笔记、任务、项目 | 标题栏「新建 ▾」 / 快速新建弹窗 / 命令 / 编辑器右键 | 原有 Inbox、项目子目录、任务总览或今日日记 |
| 完成一条任务 | 主页任务列表的勾选 | 原笔记中对应的复选框行 |
| 整理、回顾、项目梳理、关联 | AI 工作区的工作流，由 Claudian 执行 | 写入前先列计划并等待确认；不移动、不删除已有内容 |

报表保留八个顶层页面，按「总览｜行动·任务｜项目·领域·资源｜笔记·时间」分组；剪藏位于资源子页但保留独立识别范围与状态编辑。资源条目、日期、完成率和采样口径以 [REPORTING.md](REPORTING.md) 为准。历史对照中的“未覆盖”不应脱离版本直接作为当前状态。

工具区按用途分组，保留短导航；明暗主题切换与主题、强调色设置分为两个入口。复制链接、路径和定位以活动文件为边界，允许 Bases 等非 Markdown 文件；正文修改动作仍限定 Markdown。

界面使用独立的分区、文字、间距与工具排列。样式跟随 Obsidian 的主题变量，采用原生图标 API，并将覆盖样式限制在 Tangrow 容器及明确的行宽标记中。窄侧栏保留滚动和键盘焦点，正文编辑不应被定时器刷新打断。

## 首版设置中心

以下四项是设置中心第二版设计稿（本地文件 [tangrow-settings-v2.html](../output/design/tangrow-settings-v2.html)，`output/` 不入库）评审后确定的首版交互，待插件实现。兑换码、设备名额与租约续期见[购买与激活方案](PURCHASE-ACTIVATION.md)。设计稿中的邮箱登录已由兑换码激活取代，「登录更新」分区相应改名为「激活与更新」。

1. **买家用兑换码激活本机。** 「激活与更新」首屏直接显示兑换码输入框和「激活本机」按钮。未激活且尚未试用时，用户也可以直接点「开始 24 小时试用」。激活成功即显示已激活。名额已满时，同屏列出已绑定设备的平台和最近使用日期，并说明三种办法：在某台旧设备上解除本机绑定、等旧设备 45 天未使用后自动让出名额，或联系卖家。
2. **账号页用两行说明本机权益和设备。** 设置中心用一个状态点提示本机权益，位置见下文「状态点」。「本机权益」显示未开始试用、试用剩余时间、试用到期、已激活或需要联网；「已绑定设备」显示名额占用（如 2/3）并标出本机，提供「解除本机绑定」。将原买断大卡收为一句「一次购买，后续本地功能免费更新」，账号页折叠标题只写分组名称。
3. **单个设置项直接显示控件。** 在「侧边组件」直接调整默认专注时长，在「视图增强」直接切换默认加宽笔记，在「报表设置」直接填写排除目录。日、周、月、季、年五套笔记模板归入可折叠的「周期笔记模板」组。搜索「周记模板」并选择结果时，自动展开该组并定位到对应输入框。
4. **账号页底部只用一行提供更新入口。** 将独立的「插件更新」面板和帮助页重复的发布链接合并为「当前版本 v0.4.0 · 查看更新 ↗」。版本号取自已安装插件的 `manifest.json`，「查看更新」直接打开 [Tangrow 的 GitHub Releases](https://github.com/tangwz/tangrow/releases)。

### 分区与承载

设计稿的分区如下。「现有入口」列出这些设置项目前在哪里修改；迁入设置中心后，原入口怎样处理见下文。

| 分组 | 分区 | 设置项 | 现有入口 |
| --- | --- | --- | --- |
| 账号与帮助 | 激活与更新 | 兑换码激活、本机权益、已绑定设备、解除本机绑定、开始试用、版本与更新 | 新增 |
| 账号与帮助 | 使用教程 | 打开 GitHub 上的使用说明 | 新增外链 |
| 账号与帮助 | 购买与售后 | 买断范围、购买渠道、设备上限、联网要求与换机说明 | 新增 |
| 功能设置 | 默认设置 | 界面语言、启动时打开侧栏；日记目录与五种周期格式；可折叠的周期笔记模板 | 设置页 |
| 功能设置 | 目录与笔记 | 收件箱、项目、领域、资源、归档、辅助目录；任务总览笔记 | 设置页 |
| 功能设置 | 侧边组件 | 默认专注时长；AI 建议开关、模型（保留自定义模型 ID 的输入）、API 密钥 | 设置页 |
| 功能设置 | 视图增强 | 默认加宽笔记；启用知识功能、卡片目录 | 侧栏「展开全局行宽」；设置页 |
| 功能设置 | 报表设置 | 编辑活跃统计、每日活跃目标；排除目录 | 报表视图 |
| 系统设置 | 系统维护 | 初始化辅助数据库、迁移辅助目录、代理指南 | 设置页与命令 |

**承载方式。** 首版全部放在 `PluginSettingTab` 内。Obsidian 的设置弹窗已经有左侧导航，Tangrow 不再另设一栏：入口页按三个分组列出各分区及摘要，点选后在同一容器内渲染该分区，顶部保留返回入口和搜索框。这与设计稿 700px 以下的移动布局一致，桌面端与移动端共用一套结构。每个分区写成「向给定容器渲染内容」的函数，入口页、搜索跳转以及以后可能增加的独立窗口都复用这些函数。从侧栏或命令直接打开 Tangrow 设置页要用宿主未公开的设置接口，这部分放进兼容适配器；接口不可用时，提示用户从 Obsidian 设置中打开。设计稿中的「打开设置窗口」（带分区导航的完整窗口）不在首版范围内。

**保存语义。** 第 3 项的「直接显示控件」只是让单项分组不再折叠，不改变保存方式。开关和下拉改动后立即保存。整数不在每次按键时保存，而在提交（回车或数字框的 change 事件）、失焦、离开分区或关闭设置页时保存一次，同一个值不会因为这几个时机重叠而重复写入。只有与该输入框打开时显示的值或最近一次提交的值（包括还在保存中的值）不同时才会保存：没动过的输入框，或者改了又改回原值的输入框，都不会把打开设置页时的旧值写回，设置页开着时报表视图等入口改的值得以保留；上一次保存还没完成时改回原值，原值会排在它之后保存，最终结果与输入框一致。设置页开着时其他入口改了设置，没有正在编辑、也没有保存在途的输入框会改为显示新值，之后再输入原来的值就是一次真正的修改，会照常保存；正在编辑的输入框保持用户的输入。输入过程中越界时显示范围提示（专注 1–240 分钟，活跃目标 1–1440 分钟）且不保存，不再像现在一样静默忽略。保存失败时都会显示错误；只有失败的是最后一次编辑、之后也没有新的输入时，输入框才恢复为当前设置值，已被后续提交取代的失败不改动输入框。目录、周期格式、模板路径、任务总览笔记和排除目录保留「应用」按钮，因为它们要校验完整候选配置，失败时回滚；API 密钥保留「保存」。两类操作都调用现有的设置方法和串行保存队列，不新增写入路径。

**与原入口的关系。** 侧栏的「展开全局行宽」按钮，以及报表视图中的编辑活跃开关、每日目标和排除目录继续保留，作为就地调整的入口。设置中心与它们调用同一宿主方法：报表项走 `updateReportSettings`；默认加宽与侧栏按钮共用写入逻辑，同样清除仅存于内存的逐页加宽覆盖。两处界面渲染时都读取当前设置；未提交的输入只属于各自界面，不互相覆盖。

**搜索。** 每个设置项同时索引英文原文和当前语言的名称、说明，以及所属分区和分组。因此在任一界面语言下输入「weekly」或「周记」都能命中。结果按名称前缀匹配、名称包含、说明包含的顺序排列。选择结果后进入所在分区，展开所在折叠组，聚焦对应控件并短暂高亮；第 3 项的周记模板是其中一例。桌面端的 ⌘K／Ctrl K 只在设置页内监听，不注册全局快捷键。没有结果时显示「没有找到匹配的设置」。

**未开始、试用到期或需要联网时。** 功能设置与系统维护以只读方式预览，页首提示「开始试用或激活后即可调整本地功能」；需要联网时改为提示联网续期。界面语言、激活与更新、使用教程和购买与售后始终可用。能否编辑由 `access.ts` 判断，与侧栏、命令共用同一结果，见[受限范围](PURCHASE-ACTIVATION.md#受限范围)。

**状态点。** 设计稿把第 2 项的状态点放在设置中心的分区导航上。首版没有独立的分区导航，状态点改放在入口页的账号行和「激活与更新」标题旁，工作台侧栏不另加。已激活或试用中显示绿色，表示本地功能可用；试用到期或需要联网显示黄色；未开始显示中性色。颜色取自 Obsidian 主题变量，旁边始终显示状态文字，不只靠颜色区分。点击账号行进入「激活与更新」。

## 快速新建与任务

四类新建共用一个弹窗和一个输入框，减少入口之间的切换成本：第一行是标题，任务按行拆分。保存仍走既有的创建路径，不引入新的存储位置；任务只追加到已存在的任务总览或当天日记，不创建平行任务库。逐条保存任务时，已写入的行会从输入框移除，中途失败只留下未保存的部分。

侧栏采用单一全局「新建 ▾」浮层，不再保留四格新建栏或首页新建分组。浮层中的类型快捷键仅在菜单打开时有效；关闭、切页、语言切换或卸载时释放作用域。今天页保留任务行内输入与五类周期笔记，速记页保留共享输入、小窗和沉浸两个不同入口，不把上下文输入区当作重复导航删除。

侧栏勾选任务时，用索引时读到的任务文字核对目标行，行号对应的内容已变化就拒绝写入，避免在用户编辑后勾错行。写入只替换该行的复选框标记，不追加完成日期或其他属性。

## AI 功能的边界

AI 分为两层，互不依赖。

**工作流交给 Claudian。** 需要读很多文件、分多步完成的工作（整理收件箱、周回顾、任务检查、项目简报、项目拆解、关联笔记）不在 Tangrow 里实现代理，而是通过 Claudian 的插件 API 发给它当前选中的对话。这样做的理由是不重复实现工具调用、权限确认、会话历史和差异预览；Tangrow 提供的是它独有的部分：目录约定、`tangrow_` 属性和流程步骤。

- 发送的只有一段说明文字：日期、路径、约定和步骤。笔记正文由代理自己读取，Tangrow 不拼接进提示。
- 每个工作流都要求先读 `AGENTS.md`，不移动、不重命名、不删除已有内容，不改动补充目录里的数据库和记录。会写入的工作流要求先列出计划并等待用户回复；只读的工作流明确禁止修改文件。这些是写在提示里的要求，实际约束来自 Claudian 的权限设置，Tangrow 无法强制。
- 一次只跟踪一个工作流。收到 Claudian 的回合结束事件后读取最终回复并显示；停止按钮调用它的打断接口。
- 同一套步骤可以安装为库级技能（`.claude/skills/tangrow-*/SKILL.md`），只创建缺失的文件。
- Claudian 的 API 标明为实验性。每次使用时重新解析接口并核对版本号为 1，不缓存实例；缺失或不兼容时不发送，只显示引导。它仅支持桌面端，因此移动端没有工作流。
- 只调用它文档化的运行时接口、打开视图的命令和回合结束事件，不打包、不复制它的代码。

**即时建议保留内置。** 快速新建和速记处理需要立刻得到结构化结果来预填表单，Claudian 的接口是异步的且回复进入聊天记录，不适合这种交互，所以这一小块仍由插件通过官方 SDK 直接请求 Claude API。默认关闭，需要用户自己的 Anthropic API 密钥；密钥优先存入宿主密钥存储，不可用时才写入 `data.json` 并在设置中说明。

- 只在用户点击按钮时发送，内容限于正在整理的那段文字和项目笔记路径列表。
- 输入超过上限时报错并要求缩小范围，不静默截断。
- 建议只预填表单，保存由用户确认；指向不存在的项目笔记的建议会被丢弃。

## 速记日期、窗口与访问记录

月历与当日时间线按本地日期分组，优先采用有效的 `created` 属性，缺失或无效时采用文件创建时间；它们是现有速记记录上的浏览视图，不要求按日重建目录或改写旧笔记。文件时间受导入、同步或恢复影响时，只有采用该回退的记录日期可能随之变化。可选择单日或全部日期，时间线按创建时间倒序，每次加载 12 条；摘要限制为约 240 字符的纯文本，不在侧栏完整渲染或编辑 Markdown。查看全文与编辑回到原始笔记。

桌面端独立速记使用宿主分离窗口，移动端使用主区标签页。侧栏和独立视图共享 `data.json` 中的速记草稿，输入与保存通过同一状态入口处理，避免窗口各存一份导致覆盖或重复捕获。关闭窗口不改变速记的归档目录。相同草稿版本的并发提交共享一次创建；摘要清理只处理前 16,384 个 UTF-16 码元，不对全文执行正则和字符展开，过长或不完整的属性区不作为正文显示。

速记和写作提交使用持久化凭据：先保存提交身份及确定的目标路径，再创建带 `tangrow_submission_id` 的 Markdown，最后清理草稿。数据格式版本为 5，升级只增加凭据字段，不改变旧稿原文。启动和重试直接核对文件中的身份与种类；预期路径未命中时查找移动后的同一记录，不依赖可能滞后的元数据索引。创建接口写入后报错时也先核对文件，不直接重放创建。

草稿发生新编辑就解除与旧凭据的绑定，即使后来改回同样的文字也视为新稿。凭据持久化失败时不创建笔记；重试沿用原路径，不在失败后另取文件名，避免生成第二篇。恢复不修改已保存笔记，不覆盖无关占用，不在不可读时假定提交不存在。此协议覆盖单一存储状态的进程退出与重启，不把同步回滚、多个独立进程并发或旧版无凭据提交纳入事务保证。

### 速记处理

捕获与处理分开：原速记始终保留，处理后的状态由 `tangrow_processed_at` 表示，结果链接存于 `tangrow_capture_result`。时间线按待处理、已处理或全部筛选，再与日期取交集；月历仍表示全部捕获历史。恢复待处理只移除处理时间，不删除结果。

转为笔记和追加任务是两步写入，在源文件的 `tangrow_capture_processing` 中先保存动作、身份、标题和固定目标。转出笔记携带处理身份和来源链接；任务由原生 `Vault.process` 按身份标记幂等追加到既有任务页。目标成功后再写源文件的处理状态；失败时保留动作，后续继续执行同一凭据。恢复直接读取文件，支持已移动的结果和未就绪的元数据索引，不把报错视为没有写入。无关同名文件保持原样，不在重试中另选路径生成重复结果。

关联项目与单纯标记完成只修改源文件属性；项目必须是当前项目目录下已有的 Markdown，任务目标必须已经存在。多文件动作未完成时不能换成另一个动作，避免遗留不可追溯结果。处理操作复用插件串行队列，正文、未知属性和既有任务查询保持；成功返回结果位置，界面提供显式打开按钮，不在异步结束后自动切换用户的工作位置。

最近打开历史来自实际文件打开事件，以访问顺序去重并最多保留 50 个本地路径。仅在持久化历史字段缺失时从宿主 `getLastOpenFiles()` 初始化，已有空数组保持为空；宿主初始列表的容量不等于插件的 50 项上限。之后由插件跟踪 Markdown、Bases、Canvas 等实际文件访问，并维护重命名和删除后的路径；它不使用文件修改时间推断访问。既有「近期修改」Bases 仍按 `file.mtime` 查询，两种语义分开呈现。

## 周期笔记与沉浸记录

周期笔记的日期运算独立于界面语言：周采用 ISO 周一到周日，文件格式以周期起点求值，模板只在首次创建时替换固定占位符。日记继续使用原有 `journalFolder` 与 `journalFormat`，新增 `journalFormats` 与 `journalTemplates` 分别保存其他周期格式和五类模板，升级时只补默认值。路径格式可以包含子目录，解析后仍须通过库内相对路径校验。创建与设置写入复用串行操作队列，防止并发重复创建和失败设置污染后续保存。

沉浸速记复用 `CapturePanel` 的输入与提交入口，仅省略日历及时间线；关闭时释放订阅，草稿仍由插件管理。笔记沉浸仅对当前原生 `MarkdownView` 添加可撤销的布局标记与退出工具栏，不另外读取或保存正文。布局基于视图的 `ownerDocument`，适配分离窗口；退出、切换活动标签页和卸载时释放键盘事件、订阅与祖先布局标记。系统 Fullscreen API 是显式可选操作，不作为窗口内沉浸的前提。

## 语言与稳定标识

界面语言默认是简体中文，缺少语言字段的旧配置也采用中文；设置中的「界面语言」可即时切换 English。侧栏、设置、命令和提示从统一语言资源读取，语言切换保留速记输入与写作草稿。

Bases 的视图名称、列显示名以及生成的补充说明随语言变化，英文文件名与 `tangrow_` 属性键保持稳定，不重命名原笔记和目录，也不改变已有链接。升级或语言切换仅替换仍匹配已知生成版本的托管文件。数据库比较忽略 Obsidian 自动调整的 YAML 排版与对象键顺序；筛选条件、显示名、额外设置或注释有自定义修改时保留原文件。Tangrow 说明文件仍按完整文本匹配。

## 保留已有组织

补充目录默认位于笔记库根目录的 `99-Tangrow`，其他路径对应已有目录角色，都可以配置。初始化只创建 Tangrow 专属补充目录和缺失文件，且只有全部 13 个数据库与说明文件存在才视为就绪；不移动现有文件，不替换已有模板，不重写原有分类字段。对项目、领域和资源的筛选使用目录；对 Tangrow 新增记录使用 `tangrow_` 属性。

修改辅助目录或任一内容目录时都校验完整候选配置：补充目录不得等于或包含内容目录，内容目录内则可以放置专属补充子目录。升级加载时保留旧配置；若旧配置不合法，不以它排除用户笔记，并阻止向该辅助目录生成文件，等待用户修正。

修改目录设置不会改写已经存在的 Bases，避免覆盖用户对视图的调整。需要改动旧查询时，手动更新筛选条件，或选择新的补充目录后重新初始化。

提升已有辅助目录使用显式迁移入口，目标为库根 `99-Tangrow`；拒绝目标占用及源、目标之间任一方向的祖先关系，不合并、覆盖或在加载时悄悄迁移。移动前识别未定制的托管文件，移动通过宿主文件重命名接口处理链接。随后保留宿主改写的链接路径，更新未定制 Bases 与 README 中的存储路径；自定义正文和查询不以生成模板覆盖，并提示检查。

显式迁移移动整个辅助目录，包含用户放入其中的自定义笔记与其他文件。报表升级不调用该入口，加载时保留有效的旧目录配置；不能把“升级不迁移”解释成手动迁移也不移动文件。

宿主可能在目录已经移动、后续链接更新时抛错，失败恢复因此以文件的实际位置为准。回滚不会覆盖期间出现的用户编辑或原位置新增文件；若无法回到旧位置，尝试按实际落点对齐配置和未定制查询并持久化。恢复不完整时明确报错，提示核对目录位置后重试。

项目默认创建独立子目录并写入同名项目笔记，或者由用户明确选择已有项目子目录，不在项目根目录平铺 Markdown。标题日期只补充正文首个一级标题中的 ISO 日期，必要时创建标题，不重命名文件、移动路径或替换选中文字。

现有 `status: active` 可能表达项目状态，不应推断为任务未完成。正文任务由元数据索引单独读取，`[ ]` 与 `[/]` 均计入未完成；任务 Bases 明确以笔记为粒度，不宣称提供逐条复选框数据库。任务总览入口使用 `taskOverviewPath`，默认指向现有 `10-Life(Meta)/12-Tasks.md`，不改写 Tasks 查询或另建任务存储。

报表聚合现有文件与索引，状态修改只由用户显式触发。项目、领域及资源按直接子目录与根级笔记识别条目，所含笔记数另行展示；资源不显示状态。剪藏需要外部 HTTP(S) 来源或明确标记，移入资源子页不会将其限制到资源目录。总览与时间页分别记忆范围，其他页不显示无效控件；创建日多序列与 90 天新增不是历史状态快照。字词、日记与速记连续值、孤岛及随机回顾均有公开规则。

普通笔记排除范围影响正文、实体、剪藏、创建日分布与孤岛，不搬动笔记或改写 Bases；全库显式收藏与结构化专注、习惯记录保留各自范围。独立编辑活跃只保存本地事件时长桶，采用保守采样，不存正文、路径或键内容，不用专注计时或文件时间回填历史。年度笔记／收藏图与编辑活跃图的数据来源分开。

## 稳定的边界

- 插件层负责宿主交互、订阅与写入；纯逻辑模块负责时间和视图定义，便于独立验证。
- 原文写入使用公开 Vault / FileManager API；属性修改集中在用户明确触发的动作中。
- 新建文件不覆盖同名文件；同一习惯和日期、同一专注会话应有稳定记录身份，避免重复写入。
- 侧栏与独立视图共享的未提交速记、写作标题持久化在 `data.json` 的 `composer`，正文沿用 `scratch`；进行中的专注状态也持久化，暂停后的时间计算不依赖持续运行的定时器。
- 写作正文与标题由共享版本状态管理，旧版本写入和提交会被拒绝；同版本的并发归档共享一次创建。保存完成只清理该提交版本，期间的新编辑或改回原文字的操作仍保留。笔记创建成功与自动打开分开处理，打开失败不会触发再次创建。
- 中文输入法组字期间，当前写作视图持有短期内存租约，其他写作视图暂时只读；结束、切换或关闭前提交最后控件值并释放租约。草稿版本和租约仍只在内存中，提交恢复另由持久化凭据负责。
- 速记和写作暂存区用同一套规则判断一次组字是否被确认。按 Esc 结束、且之后没有再按其他键（日文输入法按 Esc 只撤回转换，继续输入仍属于同一次组字），或者结算前输入框发生失焦（点到别处、关闭视图、切换窗口或应用），视为未确认：输入框恢复为组字前的文字和光标位置，不写入草稿。其他结束方式都保留结果，包括不改变文字的提交键，如 Shift、回车、韩文音节边界、Ctrl+Space 等切换输入法的按键，以及用鼠标点选候选。Chromium 可能在结束组字后的第一个定时任务之后才派发失焦事件，所以界面短暂等待失焦，或在下一次编辑开始前先结算；关闭速记小窗或写作视图时，也先结算刚结束、仍在等待的组字。结算前速记的保存按钮不可用。
  - 失焦规则只针对还停留在拼音、罗马字或字形编码阶段的组字。组字结果全是韩文或假名时，那就是用户已经打出的字，失焦时保留，和原生应用一致；已转换成汉字的候选、夹着未转换字母的假名仍按未确认处理，Esc 仍然撤销。这条规则不影响中文拼音和英文输入；韩文、日文不在目标用户范围内，只有自动化测试，没有真机验收。
  - WebKit（iOS）把失焦引起的提交也报告为最终插入事件 `insertFromComposition`，并且先于失焦到达，所以没有失焦过的组字不以它作确认，仍等结算期结束再判断。
  - 组字结束前回到同一控件是失焦规则的例外。在该控件按下组字确认键并在退出组字状态后松开同一键，或收到最终插入事件 `insertFromComposition`，均可确认本次选词。确认键包括回车、空格、Shift、主键盘和数字小键盘上的候选编号，以及会先上屏候选再插入标点的标点键；标点在松开按键前就以普通文字插入，所以按下标点键后紧接的普通输入也算确认。仍在组字时松开的键（如拼音分隔符、翻页键）不算。最终插入可以先于结束事件，也可以在等待结算时到达。Chromium 在按下确认键时就结束组字，而正常按键要过 80–120 毫秒才松开，所以组字结束时确认键仍按着的，最多等一秒让它松开，不按短暂的失焦等待期结算；等待期间失焦则立即按未确认处理。再次失焦会清除之前的确认信号。只收到迟到的结束事件，或到结算期才重新聚焦，均恢复组字前的内容。
  - 一次组字判为未确认并恢复后，直到新的组字开始或出现普通输入，之后收到的组字结束事件都算作那次被撤回的组字。如果输入法借此把拼音放回输入框，输入框回到草稿当前保存的内容，不写入草稿。新的组字照常判断，包括在只读时开始、解锁后才选词的组字。Android 不跟踪组字，不受这条规则影响。
- 桌面端和 iOS 按上面的规则跟踪组字。Android 不跟踪：Gboard 等键盘把正在输入的整个单词都当作组字文字，那是用户的正文，按普通输入保存；代价是带行内拼音的 Android 中文输入法，可能把还没选定的拼音存进草稿。
- 写作控件的语言切换保留中文组字状态；卸载前刷新尚未发布的控件值。跨插件重载通过宿主 App 上的共享所有者与保存队列隔离旧实例，旧异步提交不得清理或持久化覆盖新实例草稿。
- 保存队列在实际写入时读取当前状态，让前序设置事务失败后的回滚先于后续草稿或卸载保存；尚未成功载入数据的实例不写卸载快照，初始化中被停用的实例不继续注册界面。
- 专注完成记录按会话身份幂等，已存在记录的分钟数作为恢复依据；习惯定义持久化失败时回滚内存状态。
- 界面计时与笔记索引更新解耦，避免每秒重建编辑区域或扫描正文。
- 核心交互使用公开宿主接口；原生主题、文件树与标签页动作隔离在兼容适配器，运行时探测能力，失败时提供操作指引，不直接写宿主私有配置。

## 已知能力边界

编辑活跃是符合条件的编辑事件间隔估算，不是完整键盘持续时长，也不记录阅读和后台时间；没有新版本以前的活跃历史。新增趋势只分组当前文件，不能还原过去的存量与状态。折叠操作使用编辑器 `foldAll` / `unfoldAll`，作用于可折叠章节，并非只处理列表。独立速记在移动端采用主区标签页，不提供桌面分离窗口。未展开的高级写作、专注和习惯行为尚未完整核验，不能据此声称完全等价。

这些属于功能缺口、行为差异或未核验范围。AI 请求依赖网络和第三方服务，模型输出可能不准确，需要用户核对；工作流还依赖用户另行安装的 Claudian 及其实验性接口。独立布局、本地数据与无需账户则是明确设计选择；来源与许可控制不应被用于掩盖功能缺口。

本轮业务实现依据现有仓库与公开 API 编写；项目历史中的参考发布文件核查仍按 [REUSE-AUDIT.md](REUSE-AUDIT.md) 记录，不以本轮未读取参考代码改写整个项目的接触历史，也不承诺零法律风险。

## 修改与撤回

停用插件即可撤去工作台和样式。原生 Bases 与已生成的 Markdown 仍可使用。移除插件前可先保留 `data.json`；它含共享速记、写作标题和正文、最近打开路径、习惯定义、卡片回顾队列及进行中的状态。是否删除补充视图、记录或笔记属性由用户自行决定，卸载不会自动删除内容。

从 `0.4.0` 起，安装脚本部署三个运行文件及 `LICENSE`、`NOTICE`、`LICENSE-MIT-LEGACY`、`THIRD_PARTY_NOTICES.md`，共七个文件，可独立备份和恢复；已有笔记和工作区不参与部署。备份目录中的 `restore.json` 记录原文件的目标位置，恢复时应先关闭 Obsidian，逐项核对后复制原文件。项目采用 GPLv3 或任何后续版本；历史 MIT 与第三方权利保持有效，宿主链接和正常输出另有附加许可。分发时须落实 GPL 对应源码义务，版本边界见 [LICENSING.md](LICENSING.md)。
