# 设计与边界

Tangrow 是现有笔记系统的补充层。目录仍表达用户原有的组织方式，Bases 提供跨目录检索，右侧工作台提供动作入口。三者各自承担清楚的职责，避免为了使用插件而迁移整个笔记库。

## 信息与动作

| 用户意图 | 侧栏入口 | 持久化方式 |
| --- | --- | --- |
| 找到最近写过的内容 | 工具 / 近期修改 | 读取宿主文件索引 |
| 新建、记录想法 | 工具 / 速记 | 原有 Inbox，或新建、明确选择的项目子目录 |
| 返回重要笔记与最近访问 | 收藏 / 最近打开 | 当前页的命名空间属性与最多 50 个本地路径 |
| 按日期回看速记 | 速记月历 / 当日时间线 | 读取记录日期，不移动文件 |
| 在独立窗口捕获 | 独立速记窗口 | 与侧栏共享持久化草稿，保存到原定 Inbox |
| 暂存写作再归档 | 写作 | 临时文本先存插件数据，转存后成为草稿笔记 |
| 记录一段专注 | 专注 | 会话状态与独立 Markdown 记录 |
| 坚持重复行动 | 习惯 | 习惯定义与按日记录 |
| 按维度浏览 | Bases 入口 | 原生 `.base` 查询配置 |
| 查看概况与任务 | 报表 / 既有任务总览 | 只读聚合与现有 Tasks 笔记 |

`0.3.0` 将报表扩展为八页；当前指标、实体识别、日期、完成率和采样口径以 [REPORTING.md](REPORTING.md) 为准。历史对照中的“未覆盖”不应脱离版本直接作为当前状态。

工具区按用途分组，保留短导航；明暗主题切换与主题、强调色设置分为两个入口。复制链接、路径和定位以活动文件为边界，允许 Bases 等非 Markdown 文件；正文修改动作仍限定 Markdown。

界面使用独立的分区、文字、间距与工具排列。样式跟随 Obsidian 的主题变量，采用原生图标 API，并将覆盖样式限制在 Tangrow 容器及明确的行宽标记中。窄侧栏保留滚动和键盘焦点，正文编辑不应被定时器刷新打断。

## 速记日期、窗口与访问记录

月历与当日时间线按本地日期分组，优先采用有效的 `created` 属性，缺失或无效时采用文件创建时间；它们是现有速记记录上的浏览视图，不要求按日重建目录或改写旧笔记。文件时间受导入、同步或恢复影响时，只有采用该回退的记录日期可能随之变化。可选择单日或全部日期，时间线按创建时间倒序，每次加载 12 条；摘要限制为约 240 字符的纯文本，不在侧栏完整渲染或编辑 Markdown。查看全文与编辑回到原始笔记。

桌面端独立速记使用宿主分离窗口，移动端使用主区标签页。侧栏和独立视图共享 `data.json` 中的速记草稿，输入与保存通过同一状态入口处理，避免窗口各存一份导致覆盖或重复捕获。关闭窗口不改变速记的归档目录。相同草稿版本的并发提交共享一次创建；如果 Markdown 已写入但草稿清理写盘失败，保留已保存的速记并重试状态持久化，不把它当作创建失败重新写入。应用在重试前退出可能令旧草稿在重启后恢复，因此不承诺进程崩溃后的跨重启去重。

最近打开历史来自实际文件打开事件，以访问顺序去重并最多保留 50 个本地路径。仅在持久化历史字段缺失时从宿主 `getLastOpenFiles()` 初始化，已有空数组保持为空；宿主初始列表的容量不等于插件的 50 项上限。之后由插件跟踪 Markdown、Bases、Canvas 等实际文件访问，并维护重命名和删除后的路径；它不使用文件修改时间推断访问。既有「近期修改」Bases 仍按 `file.mtime` 查询，两种语义分开呈现。

## 语言与稳定标识

界面语言默认是简体中文，缺少语言字段的旧配置也采用中文；设置中的「界面语言」可即时切换 English。侧栏、设置、命令和提示从统一语言资源读取，语言切换保留速记输入与写作草稿。

Bases 的视图名称、列显示名以及生成的补充说明随语言变化，英文文件名与 `tangrow_` 属性键保持稳定，不重命名原笔记和目录，也不改变已有链接。升级或语言切换仅替换仍匹配已知生成版本的托管文件。数据库比较忽略 Obsidian 自动调整的 YAML 排版与对象键顺序；筛选条件、显示名、额外设置或注释有自定义修改时保留原文件。Tangrow 说明文件仍按完整文本匹配。

## 保留已有组织

补充目录默认位于笔记库根目录的 `99-Tangrow`，其他路径对应已有目录角色，都可以配置。初始化只创建 Tangrow 专属补充目录和缺失文件，且只有全部 13 个数据库与说明文件存在才视为就绪；不移动现有文件，不替换已有模板，不重写原有分类字段。对项目、领域和资源的筛选使用目录；对 Tangrow 新增记录使用 `tangrow_` 属性。

修改辅助目录或任一内容目录时都校验完整候选配置：补充目录不得等于或包含内容目录，内容目录内则可以放置专属补充子目录。升级加载时保留旧配置；若旧配置不合法，不以它排除用户笔记，并阻止向该辅助目录生成文件，等待用户修正。

修改目录设置不会改写已经存在的 Bases，避免覆盖用户对视图的调整。需要改动旧查询时，手动更新筛选条件，或选择新的补充目录后重新初始化。

提升已有辅助目录使用显式迁移入口，目标为库根 `99-Tangrow`；拒绝目标占用及源、目标之间任一方向的祖先关系，不合并、覆盖或在加载时悄悄迁移。移动前识别未定制的托管文件，移动通过宿主文件重命名接口处理链接。随后保留宿主改写的链接路径，更新未定制 Bases 与 README 中的存储路径；自定义正文和查询不以生成模板覆盖，并提示检查。

显式迁移移动整个辅助目录，包含用户放入其中的自定义笔记与其他文件。报表升级不调用该入口，加载时保留有效的旧目录配置；不能把“升级不迁移”解释成手动迁移也不移动文件。

宿主可能在目录已经移动、后续链接更新时抛错，失败恢复因此以文件的实际位置为准。回滚不会覆盖期间出现的用户编辑或原位置新增文件；若无法回到旧位置，尝试按实际落点对齐配置和未定制查询并持久化。恢复不完整时明确报错，提示核对目录位置后重试。

项目默认创建独立子目录并写入同名项目笔记，或者由用户明确选择已有项目子目录，不在项目根目录平铺 Markdown。标题日期只补充正文首个一级标题中的 ISO 日期，必要时创建标题，不重命名文件、移动路径或替换选中文字。

现有 `status: active` 可能表达项目状态，不应推断为任务未完成。正文任务由元数据索引单独读取，`[ ]` 与 `[/]` 均计入未完成；任务 Bases 明确以笔记为粒度，不宣称提供逐条复选框数据库。任务总览入口使用 `taskOverviewPath`，默认指向现有 `10-Life(Meta)/12-Tasks.md`，不改写 Tasks 查询或另建任务存储。

报表只读聚合现有文件与索引。项目、领域按直接子目录及根级笔记识别实体，所含笔记数另行展示；剪藏需要外部 HTTP(S) 来源或明确标记。创建日多序列与 90 天新增不是历史状态快照；字词、日记与速记连续值、孤岛及随机回顾均有公开规则。

普通笔记排除范围影响正文、实体、剪藏、创建日分布与孤岛，不搬动笔记或改写 Bases；全库显式收藏与结构化专注、习惯记录保留各自范围。独立编辑活跃只保存本地事件时长桶，采用保守采样，不存正文、路径或键内容，不用专注计时或文件时间回填历史。年度笔记／收藏图与编辑活跃图的数据来源分开。

## 稳定的边界

- 插件层负责宿主交互、订阅与写入；纯逻辑模块负责时间和视图定义，便于独立验证。
- 原文写入使用公开 Vault / FileManager API；属性修改集中在用户明确触发的动作中。
- 新建文件不覆盖同名文件；同一习惯和日期、同一专注会话应有稳定记录身份，避免重复写入。
- 侧栏与独立视图共享的未提交速记、写作标题持久化在 `data.json` 的 `composer`，正文沿用 `scratch`；进行中的专注状态也持久化，暂停后的时间计算不依赖持续运行的定时器。
- 写作正文与标题由共享版本状态管理，旧版本写入和提交会被拒绝；同版本的并发归档共享一次创建。保存完成只清理该提交版本，期间的新编辑或改回原文字的操作仍保留。笔记创建成功与自动打开分开处理，打开失败不会触发再次创建。
- 中文输入法组字期间，当前写作视图持有短期内存租约，其他写作视图暂时只读；结束、切换或关闭前提交最后控件值并释放租约。草稿版本和租约不写入持久化数据，不提供跨进程或崩溃重启后的提交去重保证。
- 写作控件的语言切换保留中文组字状态；卸载前刷新尚未发布的控件值。跨插件重载通过宿主 App 上的共享所有者与保存队列隔离旧实例，旧异步提交不得清理或持久化覆盖新实例草稿。
- 保存队列在实际写入时读取当前状态，让前序设置事务失败后的回滚先于后续草稿或卸载保存；尚未成功载入数据的实例不写卸载快照，初始化中被停用的实例不继续注册界面。
- 专注完成记录按会话身份幂等，已存在记录的分钟数作为恢复依据；习惯定义持久化失败时回滚内存状态。
- 界面计时与笔记索引更新解耦，避免每秒重建编辑区域或扫描正文。
- 核心交互使用公开宿主接口；原生主题、文件树与标签页动作隔离在兼容适配器，运行时探测能力，失败时提供操作指引，不直接写宿主私有配置。

## 已知能力边界

编辑活跃是符合条件的编辑事件间隔估算，不是完整键盘持续时长，也不记录阅读和后台时间；没有新版本以前的活跃历史。新增趋势只分组当前文件，不能还原过去的存量与状态。折叠操作使用编辑器 `foldAll` / `unfoldAll`，作用于可折叠章节，并非只处理列表。独立速记在移动端采用主区标签页，不提供桌面分离窗口。未展开的高级写作、专注和习惯行为尚未完整核验，不能据此声称完全等价。

这些属于功能缺口、行为差异或未核验范围。独立布局、本地数据与无需账户则是明确设计选择；来源与许可控制不应被用于掩盖功能缺口。

本轮业务实现依据现有仓库与公开 API 编写；项目历史中的参考发布文件核查仍按 [REUSE-AUDIT.md](REUSE-AUDIT.md) 记录，不以本轮未读取参考代码改写整个项目的接触历史，也不承诺零法律风险。

## 修改与撤回

停用插件即可撤去工作台和样式。原生 Bases 与已生成的 Markdown 仍可使用。移除插件前可先保留 `data.json`；它含共享速记、写作标题和正文、最近打开路径、习惯定义及进行中的状态。是否删除补充视图、记录或笔记属性由用户自行决定，卸载不会自动删除内容。

从 `0.4.0` 起，安装脚本部署三个运行文件及 `LICENSE`、`NOTICE`、`LICENSE-MIT-LEGACY`、`THIRD_PARTY_NOTICES.md`，共七个文件，可独立备份和恢复；已有笔记和工作区不参与部署。备份目录中的 `restore.json` 记录原文件的目标位置，恢复时应先关闭 Obsidian，逐项核对后复制原文件。项目采用 GPLv3 或任何后续版本；历史 MIT 与第三方权利保持有效，宿主链接和正常输出另有附加许可。分发时须落实 GPL 对应源码义务，版本边界见 [LICENSING.md](LICENSING.md)。
