# Tangrow 首版买断、试用与设备激活方案

本文记录待实现的首版设计。官方安装包公开放在 GitHub Releases，用户可以免激活试用 **24 小时**。买家在店铺购买后收到一个兑换码，**一个兑换码最多同时激活 3 台设备**，例如一台 macOS、一台 Windows 和一部手机。一次买断覆盖当前及以后所有本地功能，包括跨大版本更新，产品标识固定为 `tangrow-local-lifetime`。

首版仅支持**小红书**与**抖音**店铺，继续发布单一官方 ZIP。源码、自行编译和再分发继续遵循[项目许可](LICENSING.md)（`GPL-3.0-or-later`）。

## 总体结构

| 组成 | 职责 | 保存什么 |
| --- | --- | --- |
| 飞书多维表格「Tangrow 授权」 | 唯一的数据存储：许可表与设备表 | 全部授权数据 |
| 授权接口（阿里云 ECS） | 校验兑换码、计算设备名额、读写飞书、签发租约 | 不保存业务数据，只有两份配置：飞书应用凭证、租约签名私钥 |
| 插件 | 激活、离线验证租约、到期前续期 | 本机设备 ID、试用记录和租约 |
| 本机制卡脚本 | 生成兑换码，输出飞书导入文件与卡密库文件 | 不保存任何东西，也不需要飞书凭证 |

插件里只有授权接口的地址，没有任何凭证。日常使用完全离线，只在激活、续期和解除绑定时联网。

## 飞书多维表格

建一个私有多维表格「Tangrow 授权」，只有你本人和授权接口使用的自建应用可以访问。该应用只开通多维表格读写权限，并且只通过「添加文档应用」加到这一个多维表格，授予可编辑权限。[飞书多维表格应用权限](https://open.feishu.cn/document/docs/bitable-v1/faq?lang=zh-CN)

### 许可表

每一行代表一份买断，一单多件时每件各占一行。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 许可编号 | 文本 | 制卡时随机生成（128 位，十六进制）。租约和设备记录都用它关联，换码时不变。 |
| 兑换码摘要 | 文本 | 规范化兑换码的 SHA-256 摘要，见[兑换码与制卡](#兑换码与制卡)。表里不存明文兑换码。 |
| 码尾号 | 文本 | 兑换码最后 4 位，方便核对。 |
| 渠道 | 单选 | 小红书、抖音。 |
| 批次 | 文本 | 制卡批次。 |
| 订单号 | 文本，按需 | 从店铺发货记录补填，原样保存，保留前导零。 |
| 状态 | 单选 | 有效、已撤销。 |
| 设备上限 | 数字 | 默认 3，个别订单可以单独调整。 |
| 备注 | 文本 | 售后记录。 |

### 设备表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 许可编号 | 文本 | 关联许可表。 |
| 设备摘要 | 文本 | 插件本机设备 ID 的 SHA-256 摘要，服务器看不到原始 ID。 |
| 平台 | 单选 | macOS、Windows、Linux、iOS、Android。 |
| 首次激活 | 日期 | |
| 最近续期 | 日期 | 每次激活或续期成功时更新。 |
| 状态 | 单选 | 有效、已释放。 |

**名额计算**：同一许可编号下，状态为「有效」且最近续期在 **45 天**内的设备才占用名额。重装、丢失或清理了数据的设备不再续期，45 天后自动让出名额，不需要你手动释放；这时它的租约（最长 30 天）早已过期。

## 授权接口

### 部署约束

- **单进程、无状态。**业务数据只读写飞书，服务器磁盘上只有配置：飞书应用的 App ID 与 App Secret、Ed25519 租约签名私钥、域名证书。配置文件权限设为 600，不进代码仓库。
- **内存中只放可丢失的临时状态**：按许可编号的互斥锁、飞书 `tenant_access_token` 缓存（2 小时有效，过期重新获取）、限流计数。重启或重新部署不丢任何业务数据。
- **只部署一个进程。**互斥锁只在单进程内有效，同一兑换码的激活请求在锁内排队，不会出现两台设备同时看到「名额未满」。以后要扩到多个进程，需要先换掉这把锁，首版不做。
- **地域与备案。**ECS 位于中国大陆地域时，用域名在 80/443 端口提供服务需要 ICP 备案；位于香港或海外地域则不需要。上线前先确定地域。
- **入口限制。**请求体上限 4 KB，读写超时 10 秒。激活按 IP 每小时 20 次、按兑换码每天 20 次限流；续期按租约每小时 5 次限流。限流主要用于保护飞书接口额度，兑换码本身有 80 位随机数，无法枚举。
- **日志。**不记录明文兑换码、完整租约或设备摘要，只记许可编号前 8 位、接口名、结果和耗时。

### 接口

| 接口 | 请求 | 处理 |
| --- | --- | --- |
| `POST /v1/activate` | 兑换码、设备摘要、平台、插件版本 | 按兑换码摘要查许可：不存在返回 404 `invalid_code`，已撤销返回 403 `revoked`。在许可锁内，本机已占名额则刷新；否则须有空位才能复用或创建设备行。成功签发 `active` 租约，无空位返回 409 `device_limit`。 |
| `POST /v1/renew` | 当前租约（可以已过期）、可选平台 | 先验签，再以飞书记录为准：许可已撤销则签发 `revoked`；设备已释放，或需要新名额但无空位，则签发 `released`。有空位但设备行缺失时，用请求平台补建；旧客户端未提供平台时返回 400 并提示重新激活。已有行沿用原平台。续期成功刷新最近续期并签发 `active`。 |
| `POST /v1/release` | 当前租约 | 把本机设备记录改为「已释放」，签发 `released` 租约。 |

三个接口的成功响应与 409 `device_limit` 都返回 `deviceLimit` 和当前占名额的设备列表（每台设备的平台、最近续期日期，以及是否为本机）。列表不签名，只用于设置中心展示。其他错误：400 `bad_request`、429 `rate_limited`、503 `upstream_unavailable`（飞书不可用）。

### 租约

租约格式为 `v1.<payload>.<signature>`，两段都用 base64url 编码，签名算法为 Ed25519，覆盖 payload 原始字节。payload 是 JSON：

| 字段 | 含义 |
| --- | --- |
| `kid` | 签名密钥编号 |
| `lic` | 许可编号 |
| `dev` | 设备摘要 |
| `st` | `active`、`released` 或 `revoked` |
| `iat` | 签发时间（Unix 秒） |
| `rnb` | 建议续期时间，`iat` + 7 天 |
| `exp` | 到期时间，`iat` + 30 天；`released` 与 `revoked` 租约没有到期时间 |
| `prd` | `tangrow-local-lifetime` |

**密钥管理。**

- 私钥只存在 ECS 配置文件和你的离线备份里。插件内置一张只读公钥表，按 `kid` 查找，不接受租约里携带的其他密钥来源。
- **常规轮换**：先发布内置新公钥的插件；大部分用户升级后，服务器改用新私钥签发。旧租约最长 30 天内会在续期时自然换成新签名。
- **私钥泄露**：立即换新私钥，并发布移除旧公钥的插件。续期以飞书记录为准，伪造的租约在续期时会被拒绝；未升级的旧版插件在租约到期前仍可能接受伪造租约，这是软门禁可以接受的残余风险。

## 兑换码与制卡

- **格式**：80 位随机数，用 Crockford Base32 编为 16 个字符，显示为 `TGRW-XXXX-XXXX-XXXX-XXXX`。
- **规范化**：去掉 `TGRW` 前缀、空格和连字符，转为大写，按 Crockford 规则把 `I`、`L` 视为 `1`，`O` 视为 `0`。插件、服务器和制卡脚本使用同一个规范化函数。
- **摘要**：对 `tangrow-code:v1:` 加规范化结果计算 SHA-256，取十六进制。
- **制卡**：在本机运行制卡脚本，指定数量、渠道和批次。脚本输出两个文件：
  - `feishu-import.csv`：许可编号、兑换码摘要、码尾号、渠道、批次、状态（有效）、设备上限（3）。导入许可表。
  - `cards.txt`：明文兑换码，一行一个。导入店铺卡密库后，删除本机的这份文件。
- **一单多件**：每件一个兑换码，各自有 3 台设备的名额。
- **换码**：码泄露或买家要求时，脚本为同一许可编号生成新码，你把新的摘要和尾号填回原行。旧码立即失效，已激活的设备照常续期。

## 售后操作

| 情况 | 你在飞书里做什么 | 生效时间 |
| --- | --- | --- |
| 买家退款 | 把许可行的状态改为「已撤销」 | 各设备下次续期时停用：联网设备 7 天内，最迟 30 天 |
| 买家换了新设备，名额已满 | 通常不用处理，旧设备 45 天未续期会自动让出名额。买家着急时，把旧设备那行改为「已释放」 | 改完后新设备立即可以激活 |
| 买家找不到兑换码 | 在店铺发货记录或许可表中按订单号、码尾号查到原码，重新发送；怀疑泄露就换码 | 立即 |
| 发现兑换码被公开传播 | 换码并联系原买家；必要时把可疑设备那行改为「已释放」 | 新激活立即失效，已激活设备下次续期时停用 |

## 许可边界与商业承诺

- **软门禁定位**：在 `GPL-3.0-or-later` 下，官方安装包与对应源码同时发布，用户享有获取、修改与再分发源码的法定权利。插件内的激活校验是面向诚实用户的软门禁（对应官方发行版的便利、持续维护与售后支持），而非强 DRM。
- **买断范围与 AI 边界**：`tangrow-local-lifetime` 覆盖 Tangrow 当前及后续版本的全部本地功能。内置即时建议所需的 Anthropic API 密钥与费用，以及第三方 Claudian 代理，不包含在买断内，须在商品页、README 与激活页明确说明。
- **设备上限与联网要求**：一个兑换码最多同时激活 3 台设备，同一台设备上的多个笔记库只算一台。激活需要联网，之后每 30 天内至少要联网一次完成续期。须在商品页和激活页明确说明。
- **终身可用兜底**：若授权服务未来停止运营，维护者将在 GitHub Releases 发布无激活门禁的官方包，避免买断用户因停服而无法使用。授权接口或飞书临时故障时，已激活的设备在租约到期前不受影响。
- **联网与隐私边界**：激活、续期和解除绑定只发送兑换码（仅激活时）、设备摘要、平台、插件版本和租约。笔记正文、目录、标签及使用统计不发送给授权服务。飞书表不保存买家的姓名、邮箱或手机号。发布时更新相关文档和设置说明。

| 买家场景 | 店铺交付 | 买家在插件里的操作 |
| --- | --- | --- |

## 插件端

兑换码输入、授权状态和版本入口的展示遵循[首版设置中心](DESIGN.md#首版设置中心)的交互决策。

由 `src/access.ts` 集中计算访问状态。侧栏、报表视图、独立速记小窗、沉浸速记、全部受限快捷命令、编辑器右键菜单、设置页与笔记沉浸入口共用同一判断；执行受限操作时按当前时间实时校验，覆盖窗口长期打开或设备休眠跨过截止时间的情况。

| 状态 | 进入条件 | 插件行为 |
| --- | --- | --- |
| 未开始 | 没有租约，也没有试用记录 | 首屏并列显示兑换码输入框和「开始 24 小时试用」。试用从用户点击时开始计时。 |
| 试用中 | 用户主动开始，且距离起点不足 24 小时 | 开放本地功能并显示截止时间。随时可以输入兑换码激活。 |
| 已激活 | 持有 `active` 租约，验签通过且未到期 | 开放全部本地功能，跨版本升级继续沿用。按时在后台续期。 |
| 需要联网 | 持有 `active` 租约但已过 `exp`，且不在试用期内 | 与试用到期相同的门禁，提示联网。联网后自动续期，成功即恢复。 |
| 试用到期 | 已过试用截止时间，且没有租约 | 保留激活、帮助、语言切换和已有草稿的只读保存与导出入口。用户可照常读写已有 Markdown 与原生 Bases。 |

判定优先级为：已激活 → 试用中 → 需要联网 → 试用到期 → 未开始，先满足哪一条就是哪一种。收到 `released` 或 `revoked` 租约时，先按下文保护草稿，再移除本机租约，按试用记录回到相应状态。

**24 小时计时与时钟回拨。**试用起点以 UTC 毫秒时间戳保存，同时维护本地已观测的最大时间戳 `maxSeenAt`。判断试用和租约是否到期时一律使用 `max(now, maxSeenAt)`，显示的试用剩余时间钳制在 `[0, 24h]`，防止调回系统时钟延长试用或租约。本地存储的 JSON 损坏或字段异常时，视为没有记录并告警，不得阻断 `onload()`。

**本机存储。**

- 设备 ID、试用记录和租约都存在 `window.localStorage`，键名分别为 `tangrow:device:v1`、`tangrow:trial:v1`、`tangrow:lease:v1`。同一台设备上的所有笔记库共用这块存储，所以一台设备只需激活一次，也只有一次试用。
- 设备 ID 是首次运行时生成的 128 位随机数，只保存在本机。对外只发送 `tangrow-device:v1:` 加设备 ID 的 SHA-256 摘要。
- 这些记录**不写入 `data.json`**，避免与草稿和设置产生写竞争，也防止租约随 Obsidian Sync、Git 或 iCloud 同步到别的设备。
- 写入包裹 `try/catch`，回读核对成功后再切换界面状态。
- 已知权衡，须在 FAQ 中说明：重装 Obsidian、清理应用数据或系统清理 WebView 缓存后，设备 ID 和试用记录都会丢失。已购用户重新激活会占一个新名额，旧记录 45 天后自动让出；清理数据也能重新试用，这是软门禁可以接受的残余。
- 实现前须在桌面端（同时打开两个笔记库窗口）和 iOS、Android 真机上确认：`window.localStorage` 确实跨笔记库共享，并且在 Obsidian 升级后保留。如果某一端不共享，那一端退回按笔记库计算设备，并在 FAQ 中说明。
- 「解除本机绑定」前弹出二次确认，提示解除后本机需要重新输入兑换码。成功后移除租约，保留试用记录。

**始终放行边界与草稿保护。**保留现有 `onload()` 的本地恢复顺序，联网续期一律在后台异步执行。即使处于「未开始」「试用到期」或「需要联网」状态，以下能力也必须始终放行：

1. **界面语言切换（`zh-CN` ↔ `en`）**：确保非中文用户在门禁页可随时切换语言完成激活。
2. **退出沉浸模式**：若进入门禁状态时正处于笔记沉浸模式（`NoteImmersion`），必须允许退出，不得将用户困在全屏布局中。
3. **已有草稿无损抢救**：定时器跨过截止时间、或收到 `released`／`revoked` 租约时，不得在用户写作或中文输入法组字中途直接销毁输入框 DOM。应先刷出未提交内容并转为**只读**，提供「保存到 Inbox」或「复制到剪贴板」出口，同时禁止继续编辑新增正文。重启后仍存在未保存草稿的，门禁页继续保留导出和保存入口。
4. **在途操作收尾**：已启动的提交凭据恢复（`recoverSubmittedDrafts`）、未完成的两步速记处理（`tangrow_capture_processing`）与进行中的专注会话完成写入（`finishFocus`）照常完成。

**网络请求与续期。**Tangrow 同时支持桌面端与移动端（`isDesktopOnly: false`）。

- 所有授权请求都通过 Obsidian 的 `requestUrl({ ..., throw: false })` 发起，绕开 Electron 与 iOS／Android WebView 的跨域限制。`requestUrl` 不支持超时参数，须在外层自建超时（交互请求 15 秒，后台续期 5 秒），并结合 `this.alive` 与请求代际号丢弃过时响应。
- 启动时以及之后每 6 小时检查一次：当前时间超过租约的 `rnb` 时发起续期。失败后按 1 小时、6 小时、24 小时退避，并加随机抖动。
- 续期结果按下表处理：

| 结果 | 处理 |
| --- | --- |
| 200，`active` 租约验签通过，`lic`、`dev` 与本机一致 | 替换本机租约，更新设备列表 |
| 200，`released` 或 `revoked` 租约验签通过，`lic`、`dev` 与当前租约一致，且 `iat` 不早于当前租约 | 保护草稿后移除本机租约 |
| 断网、超时、DNS／TLS 异常、5xx、429、非预期的 HTML 或 JSON（如公共 Wi-Fi 认证页）、验签失败 | 保留当前租约，按退避重试；到期前照常使用 |

- 验签使用纯 JS 的 Ed25519 实现，桌面端、移动端和单元测试行为一致，不依赖 `crypto.subtle`。

### 受限范围

`access.ts` 的判断接入以下位置。「受限」指在「未开始」「试用到期」或「需要联网」状态下不执行原动作，改为提示激活，并打开设置中心的「激活与更新」。入口本身保留，不从命令面板或菜单中隐藏，避免用户以为功能消失。新增命令或菜单项时必须在本表登记归类，并由测试遍历已注册命令，核对每一项都有归类。

| 入口 | 门禁状态下 |
| --- | --- |
| 功能区图标、`open-companion` | 放行，打开侧栏后显示门禁页：开始试用、输入兑换码、切换语言 |
| 侧栏五区、报表视图 | 显示门禁页；有未保存草稿时同时显示只读草稿和保存、复制出口 |
| `quick-add`、`new-note`、`new-task`、`new-project`、`new-card` | 受限 |
| `quick-capture`、`open-capture-window`、`open-immersive-capture` | 受限；已打开的独立速记或沉浸速记转为只读，保留保存和复制出口 |
| `open-daily-note` 等五个周期笔记命令 | 受限；已有的周期笔记仍可从文件树照常打开 |
| `open-assistant`、`open-report`、`pin-note` | 受限 |
| `toggle-note-immersion` | 进入受限；已在沉浸中时，退出始终放行 |
| `setup-bases`、`migrate-companion-folder` | 受限 |
| 编辑器右键的三个 Tangrow 菜单项 | 受限 |
| 设置中心 | 功能设置只读预览，语言与账号相关分区可用，见[首版设置中心](DESIGN.md#首版设置中心) |
| 提交凭据恢复、两步速记处理续写、进行中专注的完成写入 | 放行 |
| 最近打开历史 | 继续跟踪打开、重命名和删除，避免激活后路径失效 |
| 编辑活跃采样 | 停止；激活后不回填 |
| 语言切换引起的托管 Bases 与说明文件替换 | 放行，替换规则不变 |

## 不采用的方案

| 方案 | 不采用的原因 |
| --- | --- |
| CloudBase 邮箱验证码登录 | 要维护云环境、安全规则和同步工具，还要处理国内邮箱送达；插件端逻辑最多 |
| 纯离线签名许可证 | 无法限制设备数 |
| 插件直接读写飞书 | 必须把飞书应用凭证写进开源插件 |
| 用飞书工作流或集成平台做校验接口 | 多维表格工作流能否同步返回结果未确认，免费额度不明，排查困难 |
| 带数据库的完整授权服务（邮箱验证码、订单回调） | 发信、回调和数据库运维的工作量与当前规模不匹配 |

## 实施顺序、发布核对与验收

### 首版实施顺序

1. **插件离线部分**，不依赖服务器：`access.ts` 状态判定、试用计时与防回拨、设备 ID、租约验签（使用测试密钥）、受限范围接入和草稿保护。同时在三端确认 `window.localStorage` 跨笔记库共享。
2. **飞书多维表格**：建许可表和设备表；建自建应用，只开通多维表格读写权限，只添加到「Tangrow 授权」。
3. **授权接口**：实现三个接口、互斥锁、限流和飞书令牌缓存，在测试表上跑通激活、第 4 台被拒、解除绑定、撤销和 45 天让出名额。确定 ECS 地域与备案，配置域名、HTTPS 和进程守护（如 systemd 自动重启）。
4. **制卡脚本**：生成兑换码、飞书导入文件和卡密库文件，支持换码。
5. **联调**：在 macOS、Windows 和手机上各激活一台，验证第 4 台被拒、离线超过 30 天进入「需要联网」、退款后 7 天内停用。
6. **小规模上架**：先在一个店铺放少量兑换码，确认卡密库发货和激活流程。

### 发布前验收场景

| 场景 | 预期结果 |
| --- | --- |
| 新安装后首次打开，23:55 主动开始试用 | 首次打开与侧栏自动展开不计时；点击试用后可用至次日 23:55，重启和升级沿用原截止时间；将系统时钟回调 2 小时不能延长试用。 |
| 试用未开始或到期时切换语言、退出沉浸模式 | 门禁页可随时切换 `zh-CN` / `en`；处于笔记沉浸模式时到期仍可正常退出，不锁死界面。 |
| 小窗写作或中文组字中途试用到期，另一窗口有保存在途 | 未提交文本不丢失且转为只读可保存、导出，不允许继续编辑；在途保存与进行中的专注记录正常完成且不重复写入；新受限操作提示激活。 |
| 同一兑换码在 macOS、Windows、手机上激活后，再在第四台设备激活 | 返回名额已满并列出三台设备；在其中一台解除本机绑定后，第四台可以激活。 |
| 同一台电脑上打开两个笔记库 | 只占一个名额，第二个库无需重新激活，也不会再次获得试用。 |
| 已有 2 台设备时，两台新设备同时激活同一兑换码 | 只有一台成功，另一台返回名额已满。 |
| 一台设备 46 天未续期 | 不再占用名额；它再次联网续期时，名额有空则恢复，已满则收到 `released`。 |
| 退款：许可改为已撤销 | 联网设备在下次续期时收到 `revoked` 并停用，草稿保留；用该码激活新设备返回已撤销。 |
| 换码 | 旧码激活返回无效；已激活的设备续期正常。 |
| 断网、超时、5xx、429、公共 Wi-Fi 认证页 | 保留租约照常使用；租约过期后进入「需要联网」，联网后自动续期并恢复。 |
| 系统时钟回调 | 不能延长试用或租约。 |
| 伪造或篡改的租约、别人的 `revoked` 租约、更早签发的 `revoked` 租约 | 一律忽略，本机状态不变。 |
| 飞书不可用 | 激活和续期返回 503；已激活设备保留租约。 |
| 授权接口重启或重新部署 | 不丢数据，已激活设备不受影响。 |
| 密钥常规轮换 | 新版插件同时认新旧公钥；服务器换用新私钥后，旧租约在续期时换成新签名。 |
| 桌面端与 iOS、Android 真机 | 通过 `requestUrl` 完成激活和续期，Ed25519 验签结果一致。 |
