重试与幂等

tangrow_kind: drafttangrow_candidates: 3

一次支付请求超时以后，客户端会重试。如果服务端没有办法认出「这是同一次操作」，重放就会变成第二次扣款。

所以重试本身不是问题，问题是操作没有稳定的身份。幂等键应当由调用方在第一次发起时生成，并随每次重试原样带上。

设计决定

全部在 2026-11-27 评审中确定，原型按此绘制。每条第二行是没有采用的方案或相关影响，日后要改只影响对应的 PR。归档方式见第 18 条（PARA.md 6.3）。

拆成 PR 的顺序

每个 PR 都能单独合并、单独截图验收。1–4 互不依赖；5 在 2 之后；6、7 在 5 之后；9 复用 8 的「笔记库结构」组件。

实现约定

原型里所有颜色、间距和圆角都只引用 Obsidian 的 CSS 变量；顶部那段取值只是让原型在 Obsidian 之外也能渲染。

一个强调色

  • --interactive-accent 只用于：当前选中的页签下划线、每屏唯一的主按钮、开关的开启态、键盘焦点。
  • 数字、链接、日历当天、品牌图标一律用正文色或 --text-muted。

列表行透明

  • 行默认无填充，悬停用 --background-modifier-hover。
  • 分组靠 22px 段间距和 11px 小标题，不再给每块套边框卡片。
  • 只有正在操作的对象（处理面板、回顾卡片）才有边框。

三级按钮

  • 主：mod-cta，每屏最多一个。
  • 次：透明底 + --background-modifier-border 描边。
  • 文字：--text-muted，悬停变正文色。

避让状态栏

  • 侧栏滚动容器 padding-bottom: calc(var(--status-bar-scroll-padding) + var(--size-4-4))。
  • 需要在真机上确认该变量在右侧栏可用；不可用时回退到状态栏实际高度。

即将推出

  • 统一组件：灰色图标 + 一句「AI 能做什么」+ 描边小标签「即将推出」。
  • 不可点击，每页最多一处，设置里可关。

文案

  • 术语以 CONTEXT.md 为准：速记、待处理 / 已处理、卡片、主题结构、回顾、稿件、写作暂存。
  • 中文默认，英文同步；按钮写清动作（「建立 2 个缺失目录」而不是「确定」）。
