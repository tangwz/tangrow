## 产出以项目为单位（2026-11-27 评审确定）

产出的原子单位是项目，不只是写作，也不另设「产出物」概念。项目笔记用 `tangrow_project_type` 区分类型，取值由用户自己命名（写作、vlog、代码、播客只是示例），Tangrow 不预设类型表，未填为未分类；稿件、脚本、记录等照旧用 `tangrow_project` 关联项目。既不在项目目录内、也没有 `tangrow_project` 的稿件（`tangrow_kind: draft`）单列为「草稿」分类。已写入 `CONTEXT.md`（项目、领域、稿件、归档）、`docs/POSITIONING.md`（闭环图与闭环表、第 4 节、简介与演示脚本）和 `docs/PARA.md` 第 6 节，见 PR #14（分支 `claude/project-as-output`，叠在 PR #13 上）。

原型：第四个页签改为「项目」；顶部是「项目 / 领域 / 草稿」三个固定视图。「草稿」是内置分类（未归属的稿件，可逐篇「归入项目」，写作暂存也在这里），不和自定义类型混排；「项目」视图按笔记库里实际出现的类型值分组（按使用次数排序，未分类在最后，可折叠），右上角可切换成按截止日期平铺。列表顶部用浅色「+ 新建项目」行代替紫色按钮，知识页的卡片、主题结构同样处理；项目详情按 稿件与笔记 → 任务 → 资料 → 收尾 组织；主按钮看项目里有什么、不看类型名（有关联笔记时「继续：最近编辑的那篇」，没有时「打开项目笔记」），标题下的类型可点击修改；写作暂存保存时可选项目，不选就成为草稿。

## PARA 在侧栏里的位置（2026-11-27 评审补充）

PARA 只表达位置（PARA.md 第 1 节），所以不单独占一个页签，而是出现在位置真正起作用的三处：

- **整理**：「转为笔记」先问放到哪里，可选项目、领域、资源或留在收件箱，可搜索。领域和资源是新增的落点（拍板 14）。
- **项目页签**：「项目 · 领域 · 草稿」三个固定视图。领域按报表口径识别（`30-Area` 下的子目录或根级笔记），列待办数、笔记数和最近更新；领域详情是 打开领域笔记 → 待办 → 最近更新 + 「在这个领域新建笔记」。项目用可选的 `tangrow_area` 关联一个领域，领域详情列出它的项目，项目列表可按领域分组（拍板 15）。
- **知识 → 素材**：按资源条目分组（`40-Resources` 下的子目录），资源目录之外按剪藏识别的材料单列一组。每行「用于项目」只写入这篇的 `tangrow_project`。
- **项目详情**：分成「稿件与笔记」（项目产出的东西）和「资料」（拿来用的素材和卡片，标出所在位置，如「分布式系统 · 资源」）。项目和资源在单篇笔记上关联，文件不移动（拍板 16）。
- **关联操作**：草稿「归入项目」、项目详情「+ 关联」（笔记）和「+ 添加」（素材、卡片）都就地打开同一个可搜索的选择器，确认后只写 `tangrow_project`；已属于别的项目的素材会标出来。
- **任务**：项目详情的「任务」列出所有归属这个项目的未完成任务（拍板 17），每行标出来源，最多 5 条可展开；「添加任务」写进任务总览并带上 `[[项目笔记]]`。领域详情的「待办」同理。
- **归档**：项目页底「标记完成」只改状态，然后提示把项目目录移进 `90-Archive`，给出「在文件列表中定位」和「撤销完成」；在报表里把状态改成「已归档」后，项目页显示同样的提示；完成但没移走的项目在列表里标「已完成 · 待移入归档」。「一键归档」暂不占位，因为每页最多一行「即将推出」（拍板 4、18）。

## 设计决定（2026-11-27 评审全部确定）

1. **主导航**：今天 / 速记 / 知识 / 项目 / 更多，AI 不单独占页签。
2. **周期笔记子页**：取消，今天页日期旁放 日 / 周 / 月 / 季 / 年，历史日期从速记日期条打开。未采用：在速记页保留一个周期笔记子页。
3. **Claudian 工作流**：收进「更多 → 工具」，环节里只放整理引擎「即将推出」。未采用：速记页放「用 Claudian 整理收件箱」。
4. **「即将推出」占位**：每页最多一行、灰色、不可点、设置可关。未采用：E1 前不显示。
5. **引导承载**：Obsidian 弹窗。未采用：侧栏内分步。
6. **引导第 3 步时机**：现在就问、默认关、只记下选择（符合 AI-ENGINE 13.5）。未采用：E1 发布时再显示。
7. **任务标签**：显示完整标签（`#目标/写作`），多个全部显示，放不下换行。
8. **设置保存**：分区底部「保存更改」。未采用：失焦即保存。
9. **今天页速记输入**：放一行，聚焦展开。未采用：只在速记页。
10. **文件工具**：留在「更多 → 工具」改成分组列表。未采用：只留命令面板。
11. **项目类型**：不另设产出物；项目笔记 `tangrow_project_type` 区分，取值由用户自定义，其他笔记用 `tangrow_project` 关联。
12. **没有项目的稿件**：单独分类「草稿」，即 `tangrow_kind: draft`、既不在项目目录内也没有 `tangrow_project` 的稿件，不加新属性。草稿是内置分类，和「项目」「领域」并列为三个固定视图，不混进自定义类型。
13. **类型列表从哪来**：不内置、不另存，直接取笔记库里出现过的值（去空格、不分大小写合并，按使用次数排序），项目列表按类型分组、可折叠，可切换按截止日期平铺；新建或改类型时从已有值里挑或输入新值；主按钮和图标不跟类型名挂钩。未采用：设置里维护类型表（名称、顺序、图标），多一份要同步的配置，表外的值还要另行处理。
14. **领域和资源作为「转为笔记」的落点**：允许，只在所选目录新建笔记，原速记不动；要改 PARA.md 4.2 和 `capture-processing.ts`。未采用：手动处理维持「项目或收件箱」，领域和资源留给整理引擎。
15. **项目与领域的关联**：加 `tangrow_area`。项目笔记上的可选属性，一个指向领域笔记的链接，一个项目只关联一个领域，只在明确操作时写入；项目详情就地选择，领域详情列出「进行中的项目」，项目列表可按领域分组。未采用：不加；从正文链接或目录推断。（初评为「先不加」，同日复议改为加。）
16. **项目与资源的关联**：按单篇笔记关联。素材、卡片写上 `tangrow_project` 就进入项目详情的「资料」并标出所在位置；素材页每行可「用于项目」。不关联整个资源条目，不加新属性。未采用：把整个资源子目录挂到项目上。
17. **任务属于哪个项目**：不加新属性，三条规则：项目目录下笔记里的复选框；`tangrow_project` 指向该项目的笔记里的复选框；任务总览中链接到项目笔记的行（`[[重试与幂等]]`）。领域同理（领域目录 + 链接到领域笔记的行）。项目详情「添加任务」和速记「追加到任务总览」选了项目时自动带上链接。未采用：专用标签或标记；只认项目目录。
18. **完成的项目怎么归档**：现在用方案一，「标记完成」只改状态，然后提示把项目目录移进归档目录并提供定位入口，Tangrow 不移动文件；长期朝方案二（确认后由 Tangrow 移动、可撤回）迭代，引入前另行评审。已写入 PARA.md 6.3 与 CONTEXT.md「归档」。

实现时，第 8 条要改 DESIGN.md「首版设置中心」，第 14 条要改 PARA.md 4.2，均在对应 PR 中更新。
