Tangrow · 卡片笔记法（Zettelkasten）设计稿 v1

在不迁移现有目录、不改写旧笔记的前提下，给 Tangrow 补上卡片笔记法缺的几块：永久卡片、带理由的链接、卡片序列、结构笔记和回顾。所有新功能沿用 tangrow_ 属性、显式动作和幂等写入。

现有能力扩展现有模块新增

〇、卡片流转：从速记到卡片盒

卡片笔记法有四类笔记。Tangrow 已经有第一类（速记 + 处理状态），后三类只有零散的基础。

STAGE 1
闪念 已有
速记、快速新建、独立小窗、沉浸速记。处理状态存在 tangrow_processed_at。
  • 新增处理动作「提炼为卡片」
  • 支持一条速记拆成多张卡片
STAGE 2
文献笔记 部分
现在只有「剪藏」报表与 Sources 数据库，靠 source 属性识别。
  • 新增 tangrow_kind: literature
  • 显示「已提炼 N 张卡片」
STAGE 3
永久卡片 缺失
现在「笔记」只是把正文复制进 Inbox：没有 ID、没有固定位置，也不提示原子性和连接。
  • 卡片 ID、成熟度、序列（父卡片）
  • 链接时写下理由
  • 原子性提示与拆分
STAGE 4
结构笔记 缺失
没有 MOC / 索引入口。孤岛只在报表里算，侧栏看不到。
  • 结构笔记 tangrow_kind: hub
  • 列出未纳入结构笔记的卡片
  • 每日回顾队列

七、需要拍板的问题

1. 卡片放在哪里？
推荐：独立卡片目录 50-Zettel，平铺和 PARA 目录并列；Luhmann 式卡片盒不需要子目录，靠链接组织。
放进 Resources 下的子目录不新增顶层目录，但会和资源笔记混在一起。
不限目录，只靠属性识别最灵活，但新卡片仍需要一个默认落点。
2. 文件名里放不放 ID？
推荐：只用标题，ID 放在属性里[[标题]] 读起来自然；改标题时 Obsidian 会自动更新链接。
ID + 标题名字绝不重复，适合有很多相似标题的人，链接显示会长一些。
3. 要不要支持 Folgezettel（序列 / 分支）？
推荐：只做 tangrow_parent 父子关系侧栏显示树，「续写 / 分支」两个按钮。不做 1a2b 式编号。
