# 原生中文输入法验收

本轮使用 macOS、Obsidian 1.15.0 和微信输入法，在独立临时库中验收写作流程。临时库与用户的笔记、目录和未提交草稿分开；原库不创建测试笔记，也不执行迁移。

## 当前证据与边界

2026-11-09 已记录到物理键盘通过微信输入法组字并提交中文，随后通过界面保存为临时库中的草稿笔记。记录中的 `keydown`、`compositionstart`、`compositionupdate` 和正文 `input` 为可信事件；候选提交对应的 `compositionend.isTrusted` 为假。本实现不以该标志拒绝组字结束事件，也不据此推断事件由哪一层转换。

自动按键与窗口快照曾出现焦点、目标窗口不一致；宿主输入框中的拉丁文本、粘贴中文和模拟事件均不作为完整原生中文验收通过的证据。下表仍区分已观测结果与尚未完成的场景。

后续只读检查确认：临时库中的独立 Tangrow 窗口与全局 `getMostRecentLeaf()` 返回的 Markdown 叶片属于不同 document；向该接口传入来源叶片的 `getContainer()` 后，返回的叶片属于来源窗口。这个独立窗口当时只有 Tangrow 面板，因此限定窗口后的目标是面板本身。该记录验证了窗口归属问题，不能替代慢速保存期间的原生交互。

## 本轮代码修复

写作按钮显式传入来源叶片和正文控件。保存逻辑从该控件取得实际 document，并限定在来源窗口中查找 Markdown 文件视图；不再从全局最近叶片推断发起窗口。没有来源、来源窗口没有文件视图或目标被固定时，后台保存，不创建或替换面板。

慢速写入完成后，只有草稿版本、来源叶片、窗口、编辑控件、目标视图、笔记和焦点上下文均有效时，才在绑定的文件视图中打开已保存笔记。等待期间离开窗口、转移到其他控件或开始新的组字，会撤销这次导航资格；即使之后返回同一窗口和控件，也不会重新授权导航。较新的组字租约即使尚未改变草稿版本，也会阻止自动导航。正文、标题的清理仍由共享版本校验决定，完成回调不强制聚焦旧文本框。

导航上下文不可用不会把已成功的文件写入误报为失败。观察焦点和组字的临时监听器在写入成功、失败或上下文失效后释放。打开文件失败仍保留已保存结果，重试不重复创建同一草稿。

`tests/writing-origin.test.ts` 覆盖来源与全局最近叶片分属两个窗口、正常同窗口保存、离开后返回、暂时切换控件、新组字、新稿、缺少来源或文件目标、固定目标、窗口关闭、来源控件替换、目标笔记切换、写入和打开失败。它验证保存快照只写入一次、原有笔记不被修改、较新的草稿保留，以及所有最近叶片查询均限定在来源窗口。

这些回归使用模拟宿主，不能替代上表的原生输入法交互。

继续原生验收时，应在临时库分别检查同窗口文件视图、跨窗口文件视图和只有写作面板的独立窗口。在受控慢速写入期间离开后返回、切换后返回原控件，并通过微信输入法开始和取消候选；确认已有保存结果可找到、新稿保留、工作位置不被跳转、重载后草稿状态一致。需要物理输入的场景仍以原生事件及落盘结果共同验收。

```sh
npm run typecheck
npm test
npm run build
```

本轮新增修复依据当前仓库、公开宿主接口和受控输入事件独立编写，没有读取参考插件的实现代码。项目历史中的来源核查仍以既有审计记录为准。
