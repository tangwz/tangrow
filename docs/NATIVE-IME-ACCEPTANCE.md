# 原生中文输入法验收

本轮使用 macOS、Obsidian 1.15.0 和微信输入法，在独立临时库中验收写作流程。临时库与用户的笔记、目录和未提交草稿分开；原库不创建测试笔记，也不执行迁移。

## 当前证据与边界

2026-11-09 已记录到物理键盘通过微信输入法组字并提交中文，随后通过界面保存为临时库中的草稿笔记。记录中的 `keydown`、`compositionstart`、`compositionupdate` 和正文 `input` 为可信事件；候选提交对应的 `compositionend.isTrusted` 为假。本实现不以该标志拒绝组字结束事件，也不据此推断事件由哪一层转换。

自动按键与窗口快照曾出现焦点、目标窗口不一致；宿主输入框中的拉丁文本、粘贴中文和模拟事件均不作为完整原生中文验收通过的证据。下表仍区分已观测结果与尚未完成的场景。

| --- | --- |
| 微信输入法真实组字、中文候选提交 | 已观测到受控中文输入事件及最终中文 |

## 本轮代码修复

慢速写入完成后，只有草稿版本、活动叶片、视图、笔记和焦点上下文均未变化时，才自动打开已保存笔记。其他情况下保留保存结果与当前工作位置；正文、标题的清理仍由共享版本校验决定。写作按钮的完成回调不再强制聚焦旧文本框。

回归覆盖写入期间切换窗口、切换控件、切换叶片、在同一视图打开另一笔记、输入新稿以及关闭原窗口。它验证保存快照只写入一次、用户原文不被修改、较新的草稿保留，以及只有未转移的上下文才发生自动导航。

这些回归使用模拟宿主，不能替代上表的原生输入法交互。

```sh
npm run typecheck
npm test
npm run build
```

本轮新增修复依据当前仓库、公开宿主接口和受控输入事件独立编写，没有读取参考插件的实现代码。项目历史中的来源核查仍以既有审计记录为准。
